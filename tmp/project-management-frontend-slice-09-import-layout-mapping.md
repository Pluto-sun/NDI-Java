# 项目管理切片 09：导入工作表探测与字段映射

日期：2026-10-20。内部开发记录，先置于 `tmp/`。本切片延续切片 08 的逐行修正与恢复机制。

## 已实现

- 新增工作表探测接口，返回每个工作表前 12 行的非空表头候选及可映射业务字段；读取时拒绝损坏文件、外部链接、公式和过大文件。
- 预检支持选择工作表、1 起始表头行和“业务字段 → Excel 来源列”映射。未提供布局参数时，既有严格模板仍可直接预检；手工映射时，来源列不能重复，空映射保留为空值并进入逐行修正，不能暗中回退到同名列。旧模板的“`三化类别一`至`三化类别四`”可显式合并为新系统的单列类别；旧称“格物”“大数据”“万悟”和阶段“已中标”按既有业务代码识别。
- 前端在上传前可识别工作表、选择表头行并核对字段映射；预检计划保存请求的工作表、表头行和映射元数据，便于审计来源。单次仍最多 1000 条，不绕过原有权限、金额和重复校验。

## 验证范围

`./mvnw verify -q` 与前端 `npm run format:check`、`npm run build` 用于回归。新增测试覆盖非默认工作表、第二行表头、手工重命名映射、显式不映射、重复来源列拒绝以及映射布局在 MySQL 中留存。未对真实 3307 库执行导入确认；浏览器视觉与人工操作仍待本地联调。

已只读检查仓库根目录的广东预处理样例：`导入数据` 工作表有 72 行、25 列，表头包含本版要求的核心列和按日期命名的进展列；同时有待处理清单等辅助工作表。本次没有把样例逐行写入项目主档，也没有将其中客户数据复制到开发文档。

## 尚未覆盖

旧模板的多列类别虽已支持显式合并，仍需以广东真实样例做人工映射和逐行错误核对。旧系统的 7 日草稿过期和物理删除未直接照搬，需先与审计保留策略核对。项目管理其它缺口及排产、计收、能力指标三个模块的未完成范围见切片 08 文档；不能因导入路径贯通就认定全系统已复现。
