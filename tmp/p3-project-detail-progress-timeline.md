# P3：项目详情、进展与阶段里程碑切片实施记录

## 建设范围

项目创建、审批和附件已具备写入能力，但项目详情及后续进展尚无独立读取与追加入口。本切片补齐项目主档详情、进展时间线和阶段里程碑的分页接口。项目管理模块内部仍按 `controller`、`domain`、`repository`、`service`、`mapper` 分工，进展服务不承载审批或统计逻辑。

## 业务规则与数据机制

进展正文及下一步动作均为必填，去除首尾空格后写入，单字段长度上限为 10,000 字符。发生时间由服务端生成，写入人取当前认证账号。更正进展不覆盖或删除原记录，而是新增一条带 `corrects_progress_id` 的进展；应用层校验被更正记录归属，数据库复合外键再次限制跨项目引用。原始进展、后续更正与阶段里程碑均保留，按发生时间倒序分页读取。

地市负责人仅在本地市、省分负责人及本省接口人在本省范围追加进展；管理员不参与项目进展维护。读取沿用项目数据范围。用户已确认已终止项目只读：终止后保留项目详情、历史进展和里程碑的读取能力，禁止新增进展及更正。追加进展时锁定项目主档，避免与终止审批并发写入；单纯追加进展不修改项目主档版本，因此不会使已提交的阶段推进或重大变更申请无故失效。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/projects/{projectId}` | 读取项目主档详情及当前阶段、金额、责任信息、版本。 |
| `GET` | `/api/v1/projects/{projectId}/progress?page=0&size=20` | 分页读取进展及更正关联。 |
| `POST` | `/api/v1/projects/{projectId}/progress` | 追加进展；请求含 `progressContent`、`nextAction`，更正时另传 `correctsProgressId`。 |
| `GET` | `/api/v1/projects/{projectId}/milestones?page=0&size=20` | 分页读取阶段里程碑。 |

列表每页限制为 1 至 100 条。追加成功返回 `201`；空正文或下一步动作返回 `400`；无权访问返回 `403`；被更正进展不存在或不属于该项目返回 `404`；终止后追加返回 `409`。

## 验证与后续边界

MySQL 集成测试覆盖追加、更正不覆盖原记录、跨项目更正的应用与数据库双重拒绝、跨地市权限、管理员禁写、终止后只读、详情与分页接口，以及进展追加不改变项目版本且不阻断既有审批。执行 `./mvnw clean verify` 校验迁移、单元测试、集成测试和模块边界。

本切片未扩展下一步责任人、完成期限、协作需求等字段；这些字段的数据结构和校验规则在业务口径确定后再增加。历史进展与里程碑迁移属既定首轮迁移范围，在线追加接口不承担历史导入；历史导入需保留原发生时间与来源，不得伪装为当前用户的在线追加。统计月度快照也不由进展追加直接改变。
