# P3：项目审批待办与站内提醒切片实施记录

## 范围与取舍

项目审批已要求申请时指定唯一审批人，但此前只能按申请 ID 查看，指定人缺少待办入口，48 小时到期后也没有提醒记录。本切片为项目审批增加待办查询和站内通知，不改变重大变更、阶段推进的审核规则。通知暂不接入邮件或短信：当前尚无收件地址、渠道授权、送达回执与失败重试规则，先让审批节点和提醒事实在系统内可查。今后接入外部渠道时，须以站内通知或独立投递任务为来源，避免审批事务直接调用外部服务。

## 数据与处理机制

`V6` 迁移新增 `project_approval_notification`，并为审批状态与截止时间建立扫描索引。每条通知包含申请 ID、唯一收件人、事件类型、创建时间及已读时间。申请提交时通知指定审批人；审批通过、驳回或发生版本冲突时通知发起人；发起人撤回时通知原指定审批人。这些记录与对应审批状态在同一数据库事务中写入，事务失败时一并回滚。通知只保存事件类型和申请引用，申请详情仍由原有权限接口读取，不复制项目金额等业务字段。

逾期扫描在应用启动约一分钟后首次运行，随后每次执行结束 24 小时后再次运行。扫描仅覆盖截止时间已到且仍为 `PENDING` 的申请，按截止时间与申请 ID 分批续扫，避免并发处理导致页码偏移；每份申请按“截止后第几个 24 小时区间”生成提醒事件键。写入前对申请加锁并重查状态，数据库唯一键约束同一区间只生成一条提醒；多实例同时扫描也不会重复写入。应用停机跨过多个区间时，只补当前区间提醒，不补发过往每一天的通知。提醒不自动通过、驳回、升级或改变审批状态。

## 接口与运行配置

| 方法 | 路径 | 结果 |
| --- | --- | --- |
| `GET` | `/api/v1/projects/approvals/inbox?page=0&size=20` | 当前账号被指定处理的待审申请，按截止时间升序；返回逾期标志。 |
| `GET` | `/api/v1/projects/approval-notifications?page=0&size=20` | 当前账号的站内通知，按创建时间倒序。 |
| `POST` | `/api/v1/projects/approval-notifications/{notificationId}/read` | 将本人通知标记为已读；重复调用不重置已读时间。 |

接口均要求有效账号；通知详情和已读操作按收件人隔离。分页大小限制为 1 至 100。`NDI_APPROVAL_REMINDERS_ENABLED` 控制扫描开关，默认开启；`NDI_APPROVAL_REMINDER_SCAN_DELAY_MS` 与 `NDI_APPROVAL_REMINDER_INITIAL_DELAY_MS` 分别控制运行间隔和首次延迟，默认值为 86,400,000 毫秒和 60,000 毫秒。生产环境若有统一调度平台，需保留数据库事件键去重，并评估是否关闭应用内扫描。

## 验证与保留边界

MySQL 集成测试检查了指定审批人的待办范围、通知收件人隔离、提交与驳回通知、已读操作、逾期前不提醒、同一区间重复扫描去重、跨区间再次提醒，以及撤回后停止提醒。执行 `./mvnw clean verify` 验证迁移、模块边界和既有审批链路。

当前通知只有站内持久化记录，没有 WebSocket 实时推送、邮件或短信投递、未读数接口及用户通知偏好；通知留存期限也尚未定义。历史审批单不会因迁移自动补发“提交”通知；若历史待审申请仍存在，逾期扫描会按其当前状态生成提醒。这些边界不影响项目主档或审批决定的准确性，外部渠道在收件人、模板和失败处理规则确定后单独建设。
