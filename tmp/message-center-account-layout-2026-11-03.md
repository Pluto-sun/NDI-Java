# 消息审批与个人设置布局调整

本次使用 frontend-design 技能，按经营管理事项的实际处理路径调整页面。沿用现有红、白、灰配色及字体，通过业务分类、事项标题、状态、时间和操作入口建立层次，不增加装饰性统计卡片。

## 审批待办与消息通知

审批页面改为“项目审批”和“计收审核”两类，当前只展示选中的业务内容。项目审批继续保留待我审批、我发起的申请、可见审批记录及状态筛选；计收审核使用事项列表，展示通报项目名称、发起人、状态、提交时间、认定金额和详情入口。

消息页面改为“审批通知”“项目督办”“计收通知”三类。审批、计收通知使用统一的事项列表视觉结构，未读项目通过文字状态、左侧标记和浅色底突出，时间与业务归属放在次要信息行，操作入口靠右；窄屏操作移到独立行。审批通知保留仅看未读、标记已读、打开申请及分页。计收通知标记已读后更新对应状态与导航提醒。

分类选择写入 URL，刷新、前进和后退时按当前分类展示。仅加载选中业务的列表，避免同时读取多个独立内容区；导航总提醒数量仍使用原有公共计数机制。分类按钮封装为公共 `MessageCenterTabs`，计收审批和审批通知复用公共 `ListPagination`。

督办单独展示待处理、处理历史和处理过程，转发改用公共弹窗，保留原有接收人规则、备注、已读与闭环机制。标记已读仍不代表审批完成，也不关闭督办。

## 个人设置

页面只保留基本资料表单，“修改密码”入口位于基本资料标题右侧。点击后展示当前密码、新密码、确认新密码的弹窗；取消、关闭按钮或 Escape 关闭时清空密码及错误信息，焦点返回入口，不提交修改。提交过程中阻止关闭，防止请求状态不明确。

保留原有密码长度、两次输入一致性、新旧密码不能相同及服务端校验。修改成功后清空密码，所有已登录设备会话失效并返回登录页面。基本资料的姓名、邮箱保存行为保持原有规则。

## 验证结果

前端 TypeScript 检查与 Vite 构建、修改文件格式和 Git 空白检查通过。隔离环境下，审批记录、消息分类、通知计数、督办转发闭环、计收认定与导入、模块导航共 16 项桌面及窄屏回归全部通过；正式会话模式下个人资料保存、弹窗取消、清空输入、焦点返回、密码不一致、密码修改和其他设备退出共 2 项综合用例通过。视口为 1440×1000 与 375×812，窄屏启用减少动态效果。

测试使用隔离数据库和文件存储，未写入日常运行的应用库。日志位于 `/tmp/ndi-message-center-e2e.log`、`/tmp/ndi-message-center-session.log`、`/tmp/ndi-message-center-build.log`；验收截图及结构化结果保存在 `tmp/message-center-acceptance-20261103/`。实现与验证依据为本次需求、现有业务 API、组件源码和上述实际浏览器结果。
