# 计收条款编号与审签日期规范化

本次将纯数字整数条款编号按同一规则保存及判重，并扩展审签日期的常见文本格式。规则同时应用于创建、导入预检、行修正和最终导入。

## 条款编号

`002` 与 `2` 均保存为 `2`，`000` 保存为 `0`。通过字符串处理去除前导零，不转换为固定长度整数，因此保留原有 200 字上限且不产生数值溢出。`--` 继续表示无条款编号并保留原值；`A002`、`2-01`、`2.01` 等含非数字字符的文本编号保持原样。

Excel 数值单元格若实际值为非负整数，按实际整数读取，避免 `000`、`000.00` 等显示格式影响编号；文本单元格中的混合／分段编号仍作为标识处理。合同编号、业务号码／项目编号不采用该规则，仍保留前导零。

四字段唯一键继续为月账期、合同编号、规范化条款编号、业务号码／项目编号。同一账期、合同、业务号码下的 `002` 和 `2` 视为重复；业务号码不同仍允许共存。模板、映射提示和创建输入提示已同步。

## 审签日期

留空或填写 `--` 表示无日期。支持横线和斜线日期，以及空格或 `T` 分隔的日期时间，月份、日期和小时支持不补零；也支持秒、小数秒和 ISO 时区偏移。以下均保存为 `2026-07-20`：

| 输入 | 保存结果 |
| --- | --- |
| `2026-07-20` | `2026-07-20` |
| `2026/7/20` | `2026-07-20` |
| `2026-07-20 00:00:00` | `2026-07-20` |
| `2026/7/20 0:00:00` | `2026-07-20` |
| `2026-07-20T23:59:59.123+08:00` | `2026-07-20` |

先校验完整日期及时间，再提取来源日历日期，不做时区换算。`2026-02-30`、`25:00:00`、非法分钟／秒或偏移，以及多余尾随文字均拒绝；不直接截取前十位放行。原生 Excel 日期类型继续按日历日期读取。

## 既有数据升级

新增 Flyway V45。数据库增加生成的规范化条款键，唯一索引改为使用该键，阻止直接 SQL 写入等绕过应用层的同义编号。生成表达式也采用文本处理，避免长整数溢出。

升级时同步既有 `clause_no` 与来源 JSON 的条款编号，保留主档 ID、认定金额、审批申请、版本号及业务更新时间。若存在 `002`／`2` 归一后四字段冲突，原子建索引失败并保留原数据，不自动删除、覆盖或合并计收明细；应核对冲突记录后处理。已只读检查当前本地库，未发现此类冲突组，未修改该库。

重启后端时执行 V45，再刷新前端。部署到其他数据库前也应检查归一化冲突。已停留在预检页的导入任务返回字段映射后重新预检，最终确认仍按新规则复查。
