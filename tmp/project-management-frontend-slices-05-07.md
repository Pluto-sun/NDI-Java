# 项目管理前端后续切片实施记录（05 与 07 的已落地部分）

日期：2026-10-20。供项目组核对，先保存在 `tmp/`。本文只记录本轮确实实现和验证的范围，不作为“项目管理模块已完整复现”的验收结论。

## 本轮交付

切片 05 的新建表单增加了服务端草稿：创建者可以分页查看、保存、继续填写和删除自己的草稿；正式项目创建成功后，在同一事务内删除被使用的草稿。草稿不进入项目主档和统计。草稿标识无效或不属于当前账号时，新建项目会拒绝请求，避免前端误以为已消费草稿。

同地市项目名称采用统一的规范化和相似度判定。完全同名阻止新建；相似候选需要用户确认另建并填写原因，原因写入项目创建审计事件。在线新建、Excel 导入和审批改名共用地市写入锁：导入和新建不会并发写入同名项目；审批改名在实际通过前再次检查，若与现有项目重名则结束为冲突，正式项目名称不变。前端展示候选项目链接、相似度和明确的错误提示。

切片 07 只完成图形化展示的一部分：当前阶段、行业前八项、地市及历史月报阶段、近六个月趋势改为带直接数字标签的条形比较，同时保留金额文本。颜色和条长不是唯一的信息载体；没有数据时显示空状态。数据仍来自既有工作台与月末快照接口，本轮没有更改统计口径。

## 验证和边界

`./mvnw verify -q` 已通过，包含 Flyway V12 在隔离 MySQL 的回放、草稿归属与消费、重名和审批改名冲突、原有项目审批与导入集成测试。`npm run format:check` 与 `npm run build` 已通过。浏览器自动化读取本地页面受到当前环境策略限制，未进行页面视觉与人工交互验收；不能将构建成功视为浏览器验收完成。

旧 FastAPI 主档字段与 Java 当前模型仍有差异。已识别但本轮**未迁移**的旧字段包括签约主体、应用场景、产品单位支撑专家、拟招标日期和产品推广内容。其中签约主体在既定首发字段中属于必填且默认“省分签约”，应优先进入后续数据库迁移、创建/查询/导入契约及页面；其余字段应按业务价值和历史迁移口径逐项决定。现有草稿可暂存这些表单信息，但不能代替正式主档字段建设。
