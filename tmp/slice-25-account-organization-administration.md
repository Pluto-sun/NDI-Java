# 切片 25：账号与组织管理

## 交付范围与结构

本记录供项目内部维护、联调与验收使用。管理员页面接入账号查询、创建、编辑、启停、密码重置和新增地市。账号管理归入 `identity`，地市创建归入 `organization`；组织服务不反向依赖账号模块，管理员入口完成鉴权后调用组织服务。前端独立拆分列表、账号编辑、密码重置、地市创建及接口定义，复用现有表单与反馈样式。

新账号沿用旧系统的 11 位手机号规则；既有非手机号引导／演示账号允许保持原登录名编辑，但变更登录名仍须使用手机号。姓名、邮箱规范化后校验，重复账号和邮箱返回冲突。省分三类负责人允许同省兼任；地市角色必须归属有效省市；管理员、全国只读角色不绑定省市，不与业务角色混配。

## 并发、安全与数据边界

V27 增加账号管理版本，编辑、启停和重置密码均要求提交查询时的版本。个人资料或其他管理员已修改账号时，旧表单返回冲突，不覆盖新配置。账号行锁保护凭据更新，权限、属地、登录名变化以及启停、密码重置撤销旧会话；重新启用不恢复旧会话。

管理操作先取得共享管理锁，再重验操作者资格，防止等待期间已失去权限的管理员继续操作。禁止停用自己或移除自己的管理员角色，另保护最后一个已启用且设置密码的管理员。变更审计保留账号及角色、属地前后值，不记录密码和令牌。管理员即使存在历史兼任角色，项目维护和审批按钮也不显示，后端业务权限继续独立校验。

新增地市锁定父省分后检查同名记录，为地市生成独立代码，不改写既有项目和组织。账号、组织均不提供物理删除入口。小屏表格在容器内滚动，保留键盘焦点；失败表单保留输入并显示反馈，启停另行确认。

## 接口与迁移

| 路径（前缀 `/api/v1/admin`） | 行为 |
| --- | --- |
| `GET /configuration`、`GET /users` | 角色与组织选项；账号搜索、状态筛选、分页，单页最多 100 条 |
| `POST /users`、`PUT /users/{id}` | 创建；提交 `version` 和 `account` 编辑 |
| `PATCH /users/{id}/enabled` | 提交版本和目标启用状态 |
| `POST /users/{id}/reset-password` | 提交版本和新密码，撤销全部旧会话 |
| `POST /cities` | 在有效省分下新增地市 |

V27 仅新增版本列，不重写既有账号、业务数据或密码。正式模式仍使用会话 Cookie 与 CSRF，开发模式也必须通过管理员角色检查。
