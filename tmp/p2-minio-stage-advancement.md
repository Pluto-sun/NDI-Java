# P2：MinIO 资料与正向阶段推进切片实施记录

## 范围与数据流

本切片打通项目资料上传、完成校验、资料查看与正向阶段审批。`documents` 管理文件元数据和对象存储操作，`projects` 在项目属地权限通过后调用文档接口，并在审批申请中保存文档标识。文件内容不进入 MySQL，也不写入应用部署目录。

客户端先申请上传凭证，按返回的 `PUT` 地址及 `Content-Type` 请求头把文件写入 MinIO 临时对象；随后调用完成接口。服务端核对对象大小和媒体类型，把临时对象复制到仅由服务端写入的正式对象键，再流式核对正式对象的文件头和 SHA-256。校验通过后，文档状态由 `PENDING` 变为 `AVAILABLE`。阶段推进只接受本项目、用途匹配且状态为 `AVAILABLE` 的文档，避免把任意文件标识视为已上传材料。正式对象键不签发 PUT 凭证，原上传链接在有效期内再次写入临时对象，不会改变已封存内容。

## 阶段与审批规则

| 原阶段 | 目标阶段 | 申请必填内容 |
| --- | --- | --- |
| 方案交流 | 招投标 | 已完成校验的“客户侧交流方案”文档。 |
| 招投标 | 签约 | 已完成校验的“中标通知书”文档。 |
| 签约 | 计收 | 全局唯一合同编号、非负签约金额。 |

申请必须指定项目所属省份的一名接口人为审批人，提交后 48 小时到期；同一项目仍只保留一份待审申请。服务端要求目标阶段与当前阶段相邻，并校验阶段发生日期、发起人职责及项目范围。待审申请不改项目主档。审批通过后，同一数据库事务更新当前阶段、追加里程碑与版本化事件；申请提供进展和下一步动作时，两项须成对填写，审批通过后追加进展。驳回、撤回和版本冲突沿用上一切片的审批动作记录。阶段发生日期按上海时区解释，不得晚于申请当天，也不得早于最近一次生效阶段里程碑的日期。

## 联调接口与配置

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/projects/{projectId}/documents/uploads` | 申请上传，返回文档 ID、预签名 PUT 地址、请求头和到期时间。 |
| `POST` | `/api/v1/projects/{projectId}/documents/{documentId}/complete` | 封存并校验上传对象。 |
| `GET` | `/api/v1/projects/{projectId}/documents` | 列出本项目已校验的资料。 |
| `GET` | `/api/v1/projects/{projectId}/documents/{documentId}/download-url` | 获取五分钟有效的下载地址。 |
| `POST` | `/api/v1/projects/{projectId}/stage-advancements` | 提交正向阶段推进申请。 |

审批查询、撤回和决定仍使用 `/api/v1/projects/approvals/{requestId}` 下的现有接口。`local` 配置与 `docker/compose.yml` 一致：MinIO API 为 `http://localhost:9000`，控制台为 `http://localhost:9001`，默认桶名为 `ndi-documents`。本地首次上传时自动建桶；生产环境不自动建桶，须预先建桶并通过 `NDI_MINIO_ENDPOINT`、`NDI_MINIO_PUBLIC_ENDPOINT`、`NDI_MINIO_ACCESS_KEY`、`NDI_MINIO_SECRET_KEY`、`NDI_MINIO_BUCKET` 注入配置。应用在容器内运行时，内部访问地址和浏览器可访问的预签名地址应分别配置。

当前上传限制为单文件 20 MB，允许 PDF、DOCX、PPTX、PNG 和 JPEG；这是本切片的保守接入范围，不代表最终资料政策。`V5` 迁移新增文档元数据表及阶段申请字段。自动化测试覆盖 MySQL 中的阶段审批状态与合同字段、MinIO 预签名上传和对象封存，以及文档范围和用途校验，执行命令为 `./mvnw clean verify`。

## 后续治理事项

当前未接入病毒扫描、临时对象生命周期清理、文件删除审计和对象版本化备份；生产启用前须确定这些策略。审批逾期提醒、待办列表与通知投递仍由后续切片完成。文件类型与 20 MB 上限、阶段发生日期的输入方式应在前端联调时与业务方确认；调整这些规则不影响文档标识和审批表结构。
