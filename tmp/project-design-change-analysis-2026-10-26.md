# 项目设计变更分析与确认项

本文记录实施前的需求分析及确认过程；实施结果、兼容方式和验收情况见同目录 `project-design-change-implementation-2026-10-26.md`。

## 已明确的调整

驾驶舱划为四个独立查询区域，五个阶段均采用相同布局。阶段切换作为全局条件，保留各区域已选月份，不互相重置。

| 区域 | 包含内容 | 时间口径建议沿用现有规则 |
| --- | --- | --- |
| 经营总览 | 首排卡片、项目金额／数量分布、阶段／产品分布 | 项目所属月份区间 |
| 区域经营分布 | 地图、省分排名 | 项目所属月份区间 |
| 趋势分析 | 月度趋势 | 项目所属月份区间，逐月展示 |
| 近期项目变动 | 项目变动记录 | 变动发生月份 |

卡片移除上期比较，后端也停止此页面不再需要的上期聚合。四区分别加载、刷新和提示错误，不重复拉取整页数据；历史月报保持独立。地图现有高度上限为 355px、标签为 10px，调整地图与排名比例、留白、标签避让与缩放，避免单纯放大造成重叠。

项目列表问题源于筛选仅存于组件状态，详情返回链接也不带条件。建议用地址参数保存已查询条件及页码，详情携带返回上下文，并恢复滚动位置；重置筛选才清空条件。未点击查询的输入草稿与已生效条件分开保存。

人员建议存为项目下的结构化多条记录，含姓名、可空职责、可选账号关联和排序。分号仅用于 Excel 输入与展示，不作为数据库唯一存储方式。新模板合并为“项目负责人”，兼容中英文分号；旧三类字段无损转入列表，歧义项列核对清单，不覆盖原值。列表统一按负责人检索，人员修改沿用现有维护权限、审计与终止只读规则。

地区建议预置带编码、来源版本的省市目录，取消随意新增省市。已有业务引用的地区标识通过映射保留，不直接删除重建。

## 根据本轮答复确认的规则

用户已回答此前五个主体问题，以下规则取代上一版对应建议。

每个项目至少有一位项目负责人，导入时不强制关联系统账号，全部人员均允许不分配职责。详情页人员区域设“配置”按钮，通过页内弹窗配置职责与账号关联。人员职责按项目分别分配，每条人员记录至多一种职责；省分负责人至多一位，地市客户经理、产品单位支撑专家均允许多人。因允许全部未分配，省分负责人不作为必填项。

职责标签、账号关联均不自动赋予项目查看、编辑、审批或督办处理权限，现有账号权限边界保持不变。

省分层级督办优先发给项目内已分配“省分负责人”职责且已绑定的有效系统账号。否则从符合条件的省分角色账号中仅选一位接收，不再群发全部候选人。省分无人符合时立即转交负责该省的接口人，不等待原省分节点后续升级时间；接口人匹配及后续集团升级规则沿用现有配置。此前“兜底通知全部省分角色账号”及“省分无接收人时仅记录异常、不转交”的建议均作废。

“其他＋备注”需求取消，不新增“其他省份”“其他地市”或跨区域授权功能，项目继续保留唯一主归属省市。地区目录采用行政区划，不采用企业分公司口径，也不允许管理员随意新增地市。标准目录的来源版本、直辖市及省直管地区的二级节点映射应在导入前列出供核对，不能把原始目录中的缺项随意补为自定义地市。

## 本轮补充确认结论

省分负责人仅允许绑定本省已启用、具备省分角色的账号；绑定不会新增该账号原本没有的权限。账号停用或不再符合接收资格时，不继续向其发送督办，重新执行省分兜底。

省分兜底账号按登录名升序、账号 ID 升序固定排序，仅通知首位符合条件的账号，记录实际接收人。不存在合格省分账号时，立即通知负责该省的接口人，并记录转交原因。同轮通知须去重，避免即时转交后原接口人定时节点重复发送。

本轮需求澄清已闭合，足以进入切片设计及实施，不再保留前述两个业务确认问题。若负责省份未配置任何可用接口人，建议按配置异常记录并提示，不自行指定无关账号或改变集团升级规则；该异常防护不扩大既定业务范围。本轮仅确认需求，尚未修改业务代码或数据库。
