# Java 项目后续复现范围

日期：2026-10-21。本记录供项目组安排后续切片。

## 范围

本轮旧系统复现仅覆盖项目管理和支撑该模块运行所必需的平台能力。排产、计收、能力指标暂不以旧系统模型、表结构或页面为验收基准；这三个模块以后分别重新梳理业务规则，再确定数据模型与接口。项目管理代码不应提前依赖它们的旧版实体，以保留后续关联空间。

## 项目管理待核验工作

当前进展业务日期、负责人和计划完成日期已贯通，但这不代表项目管理全部完成。后续需以旧系统实际页面和接口逐项核对：项目工作台地图与省市下钻、长期未更新提醒与转发督办、资料删除及对象保留规则、项目创建时首条进展负责人可选覆盖、导入草稿保留期限，以及真实广东样例导入和浏览器流程验收。正式身份认证、账号权限管理和生产发布也需单独验收；开发态身份请求头不得作为生产方案。

旧库存在 `importance_code` 字段，默认 `NORMAL`，演示种子使用 `KEY`。旧接口接收任意字符串，前端业务页面未见稳定的取值或操作入口。因此暂不把该字段作为 Java 项目的已定版枚举；后续须确认重要度的业务含义、合法取值和审批或统计影响，再决定是否迁移。

## 验收边界

每个切片至少核对数据约束、权限、接口、页面、迁移与测试。前端构建通过只证明静态编译成立，不等同于浏览器联调。对排产、计收、能力指标的重新设计不计入“旧系统项目管理功能复现”的完成度。
