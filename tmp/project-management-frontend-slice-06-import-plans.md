# 项目管理切片 06：导入计划与选择性确认

日期：2026-10-20。本文供项目组内部核对，记录本轮实施范围与后续缺口，不作为旧系统导入功能已完整复现的证明。

## 实施范围

原导入入口只有“上传预检、确认全部有效行”两步。操作人员离开页面后难以找回预检批次，也无法排除虽通过校验但本次不拟导入的行。本轮增加本人导入计划分页查询和批次重开；每行预检通过时才显示勾选框，默认选中全部有效行以延续原操作习惯。确认请求携带所选 Excel 行号。服务端在持有批次行锁的事务中校验行号属于该批次且状态为 `READY`，重复、空选择、失败行或不存在的行均被拒绝；未选有效行转为 `SKIPPED`，选中行仍逐行重验并写入。旧无请求体的确认调用仍按“全部有效行”处理。

预检批次的创建者具备查看、选择确认及取消权限。取消仅适用于 `PREVIEWED`，结果为 `CANCELLED`，不物理删除批次、原行记录或已导入项目。此设计保留导入过程的来源证据；与旧系统“删除计划”不等价。批次列表只返回摘要，逐行内容经单独接口按创建者身份读取；`actor_id + created_at + id` 索引支持分页排序。

## 数据和状态口径

`validRows` 保留原始预检通过行数。确认完成后，`importedRows` 为实际写入数，`skippedRows` 为用户未选的有效行数，`failedRows` 为原预检失败及确认阶段写入失败的行数；三者合计等于批次总行数。批次状态沿用 `PREVIEWED → CONFIRMING → COMPLETED`，取消路径为 `PREVIEWED → CANCELLED`。页面以中文显示状态及上述数量；列表刷新失败时提示“操作已完成但列表未刷新”，避免误报为导入失败。

## 验证与剩余工作

本轮 `./mvnw verify -q` 通过（66 项测试、0 失败），其中 Testcontainers MySQL 验证了重复项目只保留首条、无效选择不改变 `PREVIEWED` 状态、选择性写入与跳过计数、他人批次不可读、取消后不能确认；`npm run format:check` 与 `npm run build` 通过。未把广东真实样例确认写入 3307 演示库。

旧系统的字段匹配、逐行修正与重新预检、模板下载、导入草稿期限和批次删除尚未实现。现有批次若在 `CONFIRMING` 阶段遇到进程中断，还缺少恢复作业；生产部署前应补幂等恢复与超时告警。下一段先保存原始单元格与修订版本，再做逐行校验和差异审计，不能直接改写已规范化的导入载荷。
