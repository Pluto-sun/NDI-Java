# 计收管理首版实施需求

日期：2026-10-30。用途：主对话开发实施交接。依据：用户提供的《计收样例.xlsx》及本对话确认结果。本文件作为本轮需求基线，替代先前字段分析与问题清单中关于省市办理归属、认定权限和审批方式的建议；旧文档仅保留讨论记录。

本轮仅整理需求，尚未实现计收业务表、接口或页面。

## 一、业务范围

集团、数科、管理员通过 Excel 导入或手动创建月度计收计划明细。省分、地市、接口人按以下权限完成认定。认定金额表示该月实际计收金额，来源本月计收金额保留原值，不因认定而被覆盖。

计收模块独立于项目管理、排产和能力指标。业务号码／项目编号是外部来源标识，不要求绑定项目管理主档。通报项目名称由认定人填写，不强制关联现有项目。

## 二、月份、金额与唯一性

计划归属月份采用“月账期”。“费用账期”独立保留，不参与计划月份归属。Excel 接收 YYYYMM，系统月份按 YYYY-MM 展示；月份必须有效。

金额统一使用元，最多两位小数，后端使用十进制定点计算，不静默截断超出精度的值。认定金额满足：

`0 ≤ 认定金额 ≤ 条款金额`

认定金额通常对应“产品本月计收不含税额/标品含税收入”，允许超过该来源金额，但不允许超过条款金额。条款金额为 0 时只能认定为 0。空认定金额表示尚未填写，与已明确认定为 0 分开处理。

原表来源金额保留其业务口径，本轮不自动进行含税／不含税换算，不将认定金额解释为回款或实收。

新增“条款编号”。月账期、合同编号、条款编号为必填，组合构成唯一标识，创建、导入及并发写入均不得重复。合同编号、条款编号、业务号码、产品编码、客户和人员来源 ID 按文本保存，保留前导零。

不得沿用项目导入的同名项目去重策略。同名项目、同一项目编号以及同一合同允许存在多条不同条款或不同月份的明细。重复唯一键按错误处理，不自动覆盖已有记录，也不静默丢弃重复行。

## 三、字段清单

首次导入由原表前 32 列增加“条款编号”，共 33 个来源字段；不导入最后四个认定字段。手动创建使用同一套来源字段，不能提前写入认定结果。模板将“条款编号”放在“合同编号”之后，通过字段映射识别，不依赖固定列号。

| 字段组 | 字段 |
|---|---|
| 账期 | 月账期、费用账期 |
| 来源组织 | 省份名称、地市/组织名称 |
| 来源业务 | 系统分类、业务号码/项目编号、项目名称 |
| 产品线 | 产品线、产品线名称 |
| 来源人员 | 项目经理ID、项目经理 |
| 合同与条款 | 合同编号、条款编号、合同名称、审签日期、条款金额 |
| 客户 | 客户名称、自然客户id、自然客户名称 |
| 产品与分类 | 产品编码、产品名称、三化分类 |
| 行业 | 一级行业编码、一级行业名称、二级行业编码、二级行业名称、三级行业编码、三级行业名称、四级行业编码、四级行业名称 |
| 其他来源属性 | 是否工业、税率、产品本月计收不含税额/标品含税收入 |

来源项目名称与通报项目名称、客户名称与自然客户名称分别保存，不互相替代。项目经理及来源人员 ID 不自动绑定账号，不授予权限。来源四级行业体系不直接套用项目管理行业字典；三化分类不按项目管理四类金额模型强制转换。

认定字段如下：

| 字段 | 规则 |
|---|---|
| 认定金额 | 必填；元，两位小数以内；非负且不超过条款金额 |
| 通报项目名称 | 必填；自由文本；不覆盖来源项目名称 |
| 项目状态 | 选填；首版沿用样例“实施中、已交付”下拉，与审批状态独立 |
| 对应省分（集成） | 选填；标准省份单选，不控制查看、认定或审批权限 |

“对应省分（集成）”不把省份和差额说明混成同一个值。本轮不根据括号中的文字自动计算金额，不建设跨省金额拆分。

## 四、组织归属

“省份名称”必须下拉选择：系统启用的标准省份，另加业务选项“具体组织”。“具体组织”是计收业务归属类型，不在组织基础目录中新建虚拟省份。

标准省份下，“地市/组织名称”仍使用文本输入，保留来源名称，不要求匹配行政地市字典，也不据此缩小到地市权限。省分和地市账号均办理本省的条目。

选择“具体组织”时，“地市/组织名称”必填，填写组织全称，例如“重庆数智融合创新科技有限公司”。该组织名称不用于推断所属省份。Excel 来源省份 `--` 归一为“具体组织”，其他无效省份值须在预检中修正；不得任意新增标准省份。

“对应省分（集成）”属于认定后的统计补充信息，改变该字段不会改变条目的原有办理权限。

## 五、角色权限

| 角色 | 查看 | 创建／导入 | 首次认定／修改认定 | 审核 |
|---|---|---|---|---|
| 管理员、集团、数科 | 全国 | 允许 | 不参与 | 不参与 |
| 省分角色 | 本省标准省份条目 | 不开放 | 提交申请，经对应接口人审核后生效 | 不审核 |
| 地市角色 | 本省标准省份条目 | 不开放 | 与省分规则相同，不按文本地市名限缩 | 不审核 |
| 接口人 | 全国，含具体组织 | 不开放 | 负责省份内直接生效；具体组织允许任意接口人处理 | 审核自己负责省份的申请 |

接口人查看全国，不代表允许直接修改全国。标准省份的办理和审核范围沿用管理员现有接口人省份配置，每省唯一接口人。省分、地市提交时绑定该省对应接口人，不提供任意审核人选择。

标准省份未配置有效接口人时，阻止省分／地市提交并提示联系管理员配置。接口人自身直接认定或修改，不再生成业务审批申请，但必须保留操作审计。

具体组织没有标准省份审批链，只由接口人直接认定和修改。省分／地市即使在“对应省分（集成）”中被填写为本省，也不会因此取得该具体组织条目的权限。

## 六、认定及修改流程

每条计收明细只有一份当前生效的认定结果。首次认定完成后，后续操作称为“修改认定”，不得另建第二份首次认定来重复累计。

省分／地市首次认定：填写认定字段，提交对应接口人审核；通过后建立生效认定结果，驳回或撤销则仍为未认定。驳回必须填写意见，提交人有权撤销自己的待审申请。

省分／地市修改认定：提交新的字段值，审核通过后替换生效结果。审核期间旧认定结果继续有效，驳回或撤销不改变旧结果；不得通过修改待审申请绕过重新提交。

接口人首次认定或修改认定：在其办理范围内直接保存生效，记录操作人、时间及修改前后值，不需要其他账号审批。

同一条目同一时间最多一条待审核申请。待审期间禁止再次修改认定、重复提交或由接口人绕过申请直接覆盖。提交人撤销、审核人通过或驳回后方可继续操作。

审批与直接修改均校验条目版本、当前账号状态、当前权限范围、金额约束及待审状态。多人或多个浏览器并发操作时，只允许符合当前版本的一次变更生效，其余返回冲突，不静默覆盖。

接口人省份配置交接时，涉及计收的待审申请应同步交给新接口人并保留交接记录；管理员实施交接不等于代审核。

## 七、导入、页面与统计实施边界

首版提供计收列表、创建、Excel 导入、详情认定／修改弹窗、审核待办及审核历史。列表至少支持月账期、省份／具体组织、来源项目／客户／合同／条款及认定办理状态检索。按账号范围展示入口与数据，后端独立校验，不能只隐藏前端按钮。

复用现有三步导入流程：文件与工作表、字段映射、预检与确认；模板与字段映射使用同一字段定义。省份名称等固定字典字段提供原生 Excel 下拉，“地市/组织名称”保持文本。样例日期需支持 Excel 日期值，`--` 按字段语义识别为缺失或具体组织，不对金额统一替换为 0。

首版最低必填来源字段为月账期、省份名称、合同编号、条款编号、条款金额、来源本月计收金额；具体组织还必须提供组织名称。其余来源字段先支持保留与选填，不因样例存在缺失而阻断，后续如需增加必填项另行调整。

单条认定金额即该条目实际计收结果，不另设“部分认定金额”和“剩余待认定金额”的余额流程。认定结果按月账期统计，同条目只计算一次，修改生效后替换旧值。待审首次认定不计入已认定金额，修改待审期间继续计入旧的已生效金额。未认定、待审核、已认定及已认定后修改待审核应在页面上区分。

本轮不额外引入月度锁定、认定截止日、逾期提醒、多级审批、历史认定结果导入、来源计划覆盖更新或删除流程。已认定或待审条目的来源关键字段不得通过普通编辑绕过认定约束；后续若开放来源更正，应另设受控流程。

## 八、验收条件

| 场景 | 预期结果 |
|---|---|
| 同月、同合同、同条款重复创建或导入 | 拒绝重复；数据库并发写入也不能产生两条 |
| 同合同同条款跨月 | 允许，分别归属各月 |
| 同项目编号、不同合同或条款 | 不按项目名称或项目编号去重 |
| 认定金额为负、超过条款金额、超过两位小数 | 拒绝 |
| 认定超过来源本月金额但不超过条款金额 | 允许 |
| 来源本月金额为 0、条款金额大于 0 | 允许提交范围内非零认定金额 |
| 认定金额为 0 | 必填校验通过，与未认定区分 |
| 本省地市账号访问本省其他地市文本条目 | 允许查看和提交认定申请 |
| 省分／地市访问外省或具体组织条目 | 拒绝 |
| 接口人查看非负责省份 | 允许查看，不允许认定、修改或审批 |
| 任意接口人办理具体组织 | 允许直接生效，不生成审批 |
| 管理员、集团、数科尝试认定或审批 | 拒绝，创建／导入权限不隐含认定权限 |
| 修改申请待审、驳回或撤销 | 原生效值保持不变，统计不采用申请值 |
| 修改申请通过 | 更新当前认定结果，保留历史，不重复累计 |
| 已有待审申请时再次修改或提交 | 阻止，包括接口人直接修改 |
| 调整对应省分（集成） | 不改变办理权限 |
| 提交缺少有效负责接口人的申请 | 阻止并给出配置提示 |
| 下载模板、映射、预检、确认 | 33 个来源字段一致；最后四项不作为首次导入字段 |

## 九、实施约束

后端沿用现有 Spring Boot、Java 21、Maven 及模块边界；计收业务按项目既有组织规范分包。复用身份、组织、消息、审批和审计的公开能力，不让计收模块直接修改其他模块持久化实体。审批治理仍为管理员不参与业务审核。

开发前检查当前仓库和主对话的最新进度，避免重复已有实现；新增代码注释使用中文，专有名词除外。需求、实施与验收文档继续写入 `tmp`。验证使用隔离数据库，执行完整 Maven Verify 和相关浏览器用例，不覆盖用户正在使用的数据。
