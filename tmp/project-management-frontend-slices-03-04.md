# 项目管理前端切片 03–04：功能对照与联调记录

日期：2026-10-20。本文是项目组内部实施记录，先放在 `tmp/`，待业务确认后再由项目负责人整理进 `docs/`。本轮继续遵循四大模块各自独立工作台的结构；前端按 `app / features / shared` 组织，项目管理的 API 统一封装在 `features/projects/api.ts`。页面沿用既有视觉规范，新增列表和预检表格保留横向滚动与可读错误提示。

## 当前判断

项目管理模块**尚未完成旧系统全部功能的复现，也未达到生产上线条件**。Java 后端已有的核心规则（主档、审批、资料、月末快照等）和新前端的主要操作链路已进一步打通；旧系统的辅助工作流、部分字段、系统管理及正式认证仍有差距，不能把“页面能访问”视为等价验收。

## 与旧系统仍有差距的部分

1. 新建项目：旧前端的草稿保存、重名候选检查与多步向导尚未复现；当前 Java 创建页是一次提交。旧系统的更多可选字段、责任信息（如产品单位支撑专家）也未全部纳入新主档，需先对照已定版字段模型再扩展，不应机械搬运旧表单。
2. 导入工作区：当前实现是“一次文件预检 → 确认全部可用行”，旧系统支持批次计划管理、逐行修正、选择性确认及删除计划。后端现有导入接口不提供这些能力；若业务仍需要，应先定版批次/行状态机与可审计操作，再扩展 API 和页面。
3. 工作台：已有当前概览、阶段/行业/地市分布与历史月报数据列表；旧系统的地图、图形化阶段趋势、时间区间与多维筛选仍未复现。新月度快照口径与旧 `project_monthly_fact` 不同，不宜直接复制旧图表查询。
4. 项目详情：审批及正式变更历史已接入；旧系统的责任信息专用修改、附件删除、更多业务字段展示与审计明细的人名化展示尚不完整。附件删除需要先明确 MinIO 对象保留和审计策略。
5. 审批与消息：普通审批通知已接入；旧系统的项目长期未更新提醒、提醒转发/接收人选择尚未迁移。管理员业务审批权限仍须按既定治理目标持续回归确认。
6. 上线基础：正式登录、用户与角色配置、备份恢复、生产身份认证、完整权限矩阵回归、前端组件/流程自动化测试及部署验收均未完成。旧系统“系统配置/个人中心”不应在缺少身份方案时直接复制。

## 人工验收入口

打开 `http://127.0.0.1:5173/`，使用演示省分负责人账号：在项目列表切换筛选并导出；进入已有项目验证普通信息表单、进展更正及项目变更历史；在审批页切换“我发起的申请”；再切换接口人账号查看审批待办与通知。导入请先用非业务样例或隔离库进行确认写入测试，避免误将真实样例写入当前演示库。
