# 切片 35：项目日期、范围筛选与历史映射

## 日期定义

项目日期独立保存为 `opportunity_date`。在线创建取创建时刻，Excel 导入取导入生效时刻，阶段推进和重大变更审批通过取审批时刻；追加进展、普通资料维护、待审、驳回、撤销及冲突均不改变它。阶段发生月份仍用于月末快照，两者不混用。

列表、详情按 `Asia/Shanghai` 展示日期，列表与导出共用起止日期条件。起日包含零点，止日包含日末微秒，与 `DATETIME(6)` 精度一致；条件直接比较列值，不对列做日期函数转换，并增加全国／省分／地市日期索引。输入限制为数据库支持的 1000～9999 年，倒置范围返回明确错误。

与旧版的差异：保留旧字段代表的原始时刻，但筛选使用系统经营时区的自然日，不沿用旧接口 UTC 日边界。页面说明该口径，浏览器端提供就近错误提示并阻止倒置查询；接口仍独立校验，不依赖前端。

## V31 升级与未知日期

V31 从创建事件、审批生效事件重建已有 Java 项目的日期，普通维护事件不参与。Excel 创建事件取导入时刻。识别到旧库来源记录或旧来源创建事件的项目，若没有后续审批证据，则保留空日期，不用旧创建时间、迁移时间或维护时间猜测。

空日期项目仍出现在不带日期的列表中；日期范围查询不纳入它们，界面提示“旧日期待核对”。本轮没有开放人工改日期的业务入口，也不把未知日期视为零值或已恢复。

## 隔离迁移工具

全量演练最低目标版本提升到 V31，直接绑定旧 `opportunity_date`，保留 UTC 时刻和微秒；源日期缺失列入失败清单，不回退到创建时间。演练技术审计时间也统一写入 UTC。

新增 `--backfill-opportunity-dates` 模式，仅根据 `LEGACY_MYSQL` 来源编号找到已有目标项目并补空日期。锁定项目行，日期更新和 `PROJECT_LEGACY_DATE_RESTORED` 审计同事务提交；已有日期不覆盖，重复执行跳过，缺来源映射或缺日期在报告中单列。提交失败不报告为已恢复。目标仍强制 `ndi_rehearsal_` 前缀，拒绝应用库 `ndi` 及源目标相同的连接。

使用具备 PyMySQL 的 Python 环境，将 `NDI_REHEARSAL_TARGET_URL` 明确指向隔离库，然后执行：

```sh
python scripts/rehearse_legacy_projects.py --source-env /绝对路径/旧服务.env --report-dir /绝对路径/隔离报告目录 --backfill-opportunity-dates
```

补回报告为 `opportunity-date-backfill.json`。工具不是业务人工补录页面，也不授权写入正在使用的业务库；本轮未对真实旧库运行此命令。

升级前应备份并演练 V31，停止旧版本后端写入后再切换，避免旧程序继续创建不含日期的新记录。不能把数据库前缀检查等同于环境隔离保证；操作者仍须核对连接目标。签约主体、建设原文等旧字段的完整迁移映射仍需独立复核，本轮不因日期绑定测试通过就宣称全字段已迁移。
