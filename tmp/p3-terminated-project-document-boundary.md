# P3：已终止项目资料写入边界切片实施记录

## 范围与规则

项目进展和普通信息维护已在已终止阶段拒绝写入，但资料上传的发起与完成此前只校验角色和属地，存在终止后继续归档资料的入口。本切片将项目资料的两个写动作纳入终态约束，不改变既有阶段推进、重大变更和资料读取接口。终止前已取得上传凭证但尚未完成校验的资料，终止后不得转为正式可用资料；已归档的历史资料仍按原有权限列出和下载。

## 事务与并发机制

发起上传与完成上传均由项目服务在一个数据库事务内先锁定项目行，随后校验账号、属地及当前阶段，再调用文档模块。终止审批同样先锁定项目行，因此上传完成与终止生效按锁顺序串行：上传先取得锁时完成流程结束后才生效终止；终止先取得锁时上传接口返回 `409 PROJECT_TERMINATED_READ_ONLY`，文档模块不会执行归档。读取接口不加项目写锁，也不因终止而隐藏既有 `AVAILABLE` 资料。接口路径和请求体保持不变，无需新增数据库迁移。

## 验证与运维边界

MySQL 集成测试覆盖终止前取得上传凭证、终止后拒绝新建及完成上传、历史资料继续列出和下载、HTTP 错误码，以及完成上传与终止审批的项目行锁串行行为。完整构建执行 `./mvnw clean verify`，其中 MinIO 集成测试继续验证对象上传与封存链路。

预签名上传链接有效期为 10 分钟。项目终止后，已发出的链接在过期前仍可能写入 MinIO 暂存键，但因完成接口拒绝归档，该对象不会成为业务可读的正式资料；未完成的元数据仍处于 `PENDING`，现有列表不会展示。暂存对象与过期 `PENDING` 元数据需要独立清理策略，尤其要避免误删仍在上传期的对象。完成接口当前持有项目锁期间会执行对象校验，单文件上限为 20 MB；生产数据量和存储延迟上升后，应监测锁等待并评估拆分校验与业务生效步骤。
