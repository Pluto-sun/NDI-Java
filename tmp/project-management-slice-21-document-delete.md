# 切片 21：项目资料受控删除

## 范围与决定

本切片只处理项目管理资料，不涉及排产、计收、能力指标。旧系统支持上传者所在项目权限范围内的附件删除，审批已引用的附件不可删除。新版沿用业务约束，但采用元数据软删除：资料立即从项目列表、下载和后续审批材料候选中消失；MinIO 对象暂留，用于审计与后续保留期治理。对象清理策略应另行定版，不能在业务请求中直接物理删除。

## 实现

- 项目资料增加 `DELETE /api/v1/projects/{projectId}/documents/{documentId}`，由项目模块检查当前项目的协作权限和终止后只读规则，由文档模块校验资料归属并更新状态。
- 审批申请中曾引用的材料一律拒绝删除，包括已通过、驳回、撤销的申请；事务回滚软删除状态，避免审批审计失去材料关联。
- 被删除资料不得再完成上传校验、作为有效审批材料或取得下载地址。
- 列表和下载改用项目数据读取权限，允许全国只读角色查看其有权访问的项目资料；上传、删除仍需要项目协作权限。
- 前端资料列表加入删除操作、确认和操作反馈，项目只读时不显示删除入口。

## 验证

- 文档服务单测覆盖跨项目拒绝、软删除后的不可用状态与上传完成拦截。
- 项目集成测试覆盖全国只读用户可读不可删、审批引用保护、正常删除接口。
- 已运行 `./mvnw -q verify`，前端已运行 `npm run format:check && npm run build`，均通过；集成测试使用隔离 MySQL／MinIO 容器，未改动本地 3307 业务库。
