# 切片 24：正式会话与个人设置

## 本次交付

本记录供项目维护与内部验收使用。认证归入 `identity` 模块，密码编码、资料维护、会话处理分别组织；共享安全层通过目录接口解析会话，不反向依赖账号模块。个人资料仅开放姓名、邮箱，角色和属地不接受本人修改。

正式模式使用数据库会话及 HttpOnly、SameSite=Lax Cookie。密码由 Spring Security 的 PBKDF2 编码器处理，原始会话令牌只进入 Cookie，数据库保存 SHA-256 摘要。每次请求重验账号启用状态、会话期限及凭据版本。退出撤销当前 Cookie 对应会话；密码修改在账号行锁内提升凭据版本并撤销全部旧会话，避免与并发登录交错后残留有效旧凭据。成功登录、退出、资料修改、密码修改及首次管理员初始化均记录审计，不记录秘密值。

浏览器按服务端认证模式显示密码登录或开发账号选择。正式模式停用身份请求头和开发账号目录，写请求使用 Spring Security 的 CSRF Cookie 与请求头；校验失效仅刷新令牌重试一次。密码表单支持自动填充和粘贴，资料保存失败保留输入，密码修改成功后明确提示重新登录。沿用现有视觉规范，跳转主内容链接按自身高度隐藏，并验收聚焦前后的可见性。

## 启动与配置

| 配置 | 行为 |
| --- | --- |
| `NDI_AUTH_MODE=SESSION` | 启用正式登录；本地 IDEA 也通过环境变量设置 |
| `NDI_AUTH_MODE=LOCAL_ACTOR` | 仅允许 `local` 环境；本地默认保留原联调方式 |
| `NDI_SESSION_TTL_HOURS` | 绝对有效期，默认 8 小时，范围 1～168 小时 |
| `NDI_SECURE_COOKIE` | 非本地默认 `true`，要求 HTTPS；本地 HTTP 默认 `false` |
| `NDI_BOOTSTRAP_ADMIN_LOGIN` / `NDI_BOOTSTRAP_ADMIN_PASSWORD` | 首次管理员显式配置，密码 6～128 字符；无默认口令，不写入仓库 |

已有可登录管理员时不覆盖密码；配置与已有非管理员或停用账号冲突时启动失败。首次初始化后应移除引导凭据。V26 为增量迁移，既有账号密码为空时不能通过密码登录，不自动为历史账号设置统一密码。其他账号开通、重置密码和组织维护由后续管理切片补齐。

## 接口清单

| 方法与路径（前缀 `/api/v1/auth`） | 用途 |
| --- | --- |
| `GET /mode`、`GET /csrf` | 认证模式、写请求校验令牌 |
| `POST /sessions`、`DELETE /sessions/current` | 登录、退出当前会话 |
| `GET /me`、`PUT /me` | 本人资料查询、修改 |
| `POST /password` | 校验当前密码、修改并撤销全部会话 |

## 验收与边界

验证使用一次性 MySQL 与 MinIO，不写本地 3307 业务库。认证集成测试覆盖 CSRF、身份头隔离、令牌摘要、到期、停用、凭据版本、双会话退出、密码变更及邮箱冲突；浏览器覆盖桌面与 375px 的登录、保存、刷新、退出及跨设备撤销。最终运行结果见本节后续记录。

该切片不等于上线安全验收。登录限流、失败审计与告警、密码策略强化、过期会话清理仍需上线前补齐；HTTPS 和代理边界配置须在实际部署环境验证，不由本地测试替代。后续还包括账号组织管理、多省接口人范围、备份恢复、全局未读提示及完整业务浏览器验收。

素材使用：旧系统 `backend/app/api/routers/auth.py` 用于功能核对；本次源码和测试结果用于实现说明；技能知识库“测试金字塔”用于安排接口与浏览器分层验证，“安全与等保”仅用于识别上线边界，不据此宣称通过任何合规测评。
