# 切片 22：项目超时督办

## 业务规则

连续 30 天未变动时通知项目已指定的省分负责人；该账号停用或失去资格时，回退到本省启用的省分负责人。33 天升级到本省接口人，36 天升级到集团、数科、数智和广东 DPASS。每日上海时间 09:00 扫描；首次扫描已超过某级阈值时，从当前级别发起，沿用旧版行为。管理员不接收或转发业务督办。

省分负责人转发给项目所属地市三化负责人；接口人和集团角色转发给同省三化负责人。接收人需启用且职责、属地匹配，备注必填。同一接口人层级由其中一人转发后，共享待办转入历史；地市按周期聚合一条通知，保留每次转发备注。督办不提供任意标记已读，项目有效更新后闭环。

## 状态与并发

`V24` 新建活动状态、督办周期、接收通知和转发记录表。活动修订独立于审批主档版本：追加或更正进展重置督办计时，保留既有“不使在途审批失效”的契约。普通资料实际变更、重大变更或阶段推进获批，在原事务内更新活动状态并闭环；无变化提交、待审、驳回、撤销不闭环。终止获批时闭环，已终止项目不再发起督办。

扫描、转发和项目更新共用项目行锁，周期与通知另设唯一约束。锁后读取使用当前读，避免并发重复转发；督办写入事务使用 READ COMMITTED，避免不同项目首次建周期时相互持有空范围锁。缺少接收人时不标记发送成功，保留告警并在后续扫描重试。活动游标和索引支持分批扫描；时间按 UTC 持久化。升级回填取原主档修改时间和最近进展时间的较大值，保留原审批版本。

## 接口与界面

消息通知页增加待处理、处理历史、处理链、转发备注和项目跳转。接口位于 `/api/v1/projects`：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /inactivity-notices` | 当前接收人的分页督办，支持 `history` |
| `GET /inactivity-cases/{id}/recipients` | 当前待办的合资格转发对象 |
| `POST /inactivity-cases/{id}/forward` | 转发并保留处理记录 |
| `POST /admin/inactivity-reminders/trigger` | 管理员按 30／33／36 天演练，不修改实际活动时间 |

配置项为 `NDI_PROJECT_INACTIVITY_ENABLED` 和 `NDI_PROJECT_INACTIVITY_CRON`。身份模块统一判断接收和转发资格。

## 验证与复跑

工程依据：旧版 `scheduler.py`、`project_service.py` 的督办实现；验证证据见 `ProjectInactivityIT`、`ProjectActivityMigrationIT` 和 `frontend/e2e/inactivity.spec.ts`，分别覆盖业务、升级与浏览器交互。
