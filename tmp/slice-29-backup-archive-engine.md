# 切片 29：成对归档引擎与隔离恢复演练

## 交付范围

本记录供项目开发维护留档。本切片实现备份引擎，尚不提供管理员创建任务、记录列表及下载页面，不能据此认定备份功能已完成复现。

新增独立 `backup` 模块，按 `config / domain / mapper / service / util` 分工；SQL 查询留在 mapper，归档编排留在 service，对象读取通过 documents 的公开服务接口完成。未向业务模块暴露 MinIO 凭据。

## 归档口径

同一 MySQL InnoDB 只读快照确定建表语句、全部表数据与正式对象清单，完成 SQL 后释放读事务，再流式归档对象。备份期间禁止发布结构迁移；前后结构核对仅作额外保护，不替代运维约束。该边界与 [MySQL 一致性读取说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-consistent-read.html) 一致。

归档包含 `database.sql`、版本化 `manifest.json` 和编号化对象条目。覆盖 AVAILABLE、DELETED 资料及 COMPLETED 项目导出；PENDING 元数据保留，但不复制未完成的暂存上传，恢复后须重新上传。软删除状态不因备份而解除。

每份资料核对数据库登记的大小及 SHA-256；导出文件计算摘要。清单记录表行数、对象位置与摘要，整个 ZIP 另有 SHA-256。生成列表达式随建表语句恢复，不直接插值。文本与二进制值采用十六进制编码，布尔值按数值还原，避免中文、引号、换行或零字节破坏语句。

## 失败与保密

工作进程以数据库会话锁互斥；失败删除临时文件，不覆盖同编号归档。文件持久化、完整性复核后原子发布。校验器拒绝额外路径、重复条目、摘要不符与超出容量的内容，不解压、不执行 SQL。

新目录权限 0700、文件 0600。归档包含客户数据、密码摘要和资料，保密级别等同生产库，不得放入静态目录或公开桶。当前未实现加密、异地复制和保留策略，不宣称已达到生产容灾要求。非 InnoDB 表、视图、触发器、存储过程或事件会明确拒绝，不静默遗漏。

## 配置与依据

| 环境变量 | 默认值 |
| --- | --- |
| NDI_BACKUP_DIRECTORY | ./var/backups |
| NDI_BACKUP_MAX_BYTES | 解压总量 2 GiB |
| NDI_BACKUP_MAX_OBJECTS | 10000 |
| NDI_BACKUP_TIMEOUT_SECONDS | 600 |

部署应将目录挂载到独立受限存储。运行时预算在读取间检查，单次对象请求另设 120 秒调用、30 秒读取超时；清单限 8 MiB、单元格限 16 MiB。

对照来源为旧版 `backend/app/api/routers/storage.py`；验证入口为 `BackupArchiveIT`。文档技能知识库《高可用集群与故障转移》的“风险与边界”用于区分归档恢复与服务高可用，不引用未经实测的 RPO、RTO 数字。

## 验证结果（2026-10-21）

`mvn -q clean verify` 通过：46 项单元／契约／架构测试、90 项集成测试，错误、失败、跳过均为零。随后补强同大小损坏文件的摘要断言，5 项归档集成测试再次通过。前端格式检查和生产构建通过，本切片无页面变更，未新增浏览器流程。

归档测试在独立 MySQL、MinIO 中生成备份，并向另一组空 MySQL、MinIO 还原；核对全部表行数、待审申请生成列、中文与零字节文本、JSON、二进制、正负金额、布尔真假、空值、微秒时间及全部正式对象摘要。并发业务修改不会进入已建立的快照。另验证缺失对象、同大小损坏对象、容量超限、额外路径、SQL 篡改、重复编号与工作进程互斥。

未访问本地 3307 应用库执行归档或恢复。管理员任务创建、列表、受控下载和可执行恢复规程留待下一切片接入，归档文件需继续通过受信任记录保存外层摘要。
