# 本机与局域网访问配置

`localhost` 与 `127.0.0.1` 都指向访问者自己的电脑。其他设备访问本项目应使用运行服务的 Mac 的局域网 IP；服务监听 `0.0.0.0` 才能接收其他设备的连接，`0.0.0.0` 本身不作为分享给用户的访问地址。

本次已将前端默认监听改为 `0.0.0.0:5173`，并重启原前端进程。当前地址为：

- 本机：`http://localhost:5173`
- 同一局域网内其他设备：`http://192.168.8.102:5173`

前端 `/api` 继续代理到本机 `http://127.0.0.1:8080`。后端仍监听回环地址，当前运行在 IDEA 中，本次没有重启后端或修改数据库。其他设备无需直接连接 8080。不同访问地址属于不同浏览器来源，首次切换地址需要重新选择账号或登录。

## 后续启动

在 NDI-Java 根目录运行 `./scripts/start-frontend.sh`。脚本默认监听全部 IPv4 网卡，并显示本机与检测到的局域网地址。`npm --prefix frontend run dev` 同样采用新的默认监听配置。

临时只开放给本机：`NDI_FRONTEND_HOST=127.0.0.1 ./scripts/start-frontend.sh`。自定义端口继续使用 `NDI_FRONTEND_PORT=5174 ./scripts/start-frontend.sh`；前端自动化验收显式使用回环监听，保持测试环境的原有边界。端口占用时直接报错，避免自动换端口。

当前前端运行日志：`tmp/lan-frontend-runtime-2026-11-10.log`。启动脚本为前台命令；后续从自己的终端启动时，按 Ctrl+C 停止。IP 地址由当前网络分配，更换 Wi-Fi 或 DHCP 重新分配后应重新确认地址，脚本不会把当前 IP 写死到项目配置中。

## 附件与对象存储

当前 local 配置的 MinIO 外部地址默认为 `http://localhost:9000`，预签名上传及下载链接会使用该地址。该默认值对其他设备无效。在 IDEA 的 NdiApplication 运行配置中增加环境变量 `NDI_MINIO_PUBLIC_ENDPOINT=http://192.168.8.102:9000`，再重启后端；内部存储连接 `NDI_MINIO_ENDPOINT` 仍可使用 localhost，无需调整数据库连接。Docker 已映射 9000 端口。预签名 URL 不能由浏览器随意替换域名或端口，否则签名可能失效。

本次没有修改正在运行的 IDEA 环境变量，因此页面与 API 已开放局域网访问，附件外部链接需按上述步骤单独启用。若其他设备仍无法打开页面，应确认处于同一局域网、macOS 允许 Node 的入站连接，且无线网络没有开启客户端隔离。

## 验证

监听检查确认前端为 `*:5173`，后端仍为 `127.0.0.1:8080`，后端进程 PID 未变化。`http://localhost:5173/`、`http://192.168.8.102:5173/` 与通过局域网前端访问的 `/api/v1/auth/mode` 均返回 HTTP 200。验证来自当前 Mac 经局域网 IP 的请求，尚未在第二台设备上实测。前端 TypeScript／Vite 构建、启动脚本语法检查和修改文件格式检查通过。
