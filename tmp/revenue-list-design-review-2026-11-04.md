# 计收列表设计检查与优化记录

本次使用 frontend-design 检查计收列表，供项目维护人员留档。主要问题是自动列宽导致表头与状态竖向堆叠、金额列未对齐、筛选控件空间分配不均，以及汇总区的独立卡片削弱了数据之间的关系。

## 设计与实现

沿用联通红 #d82735、深红 #aa1b28、正文 #2c2023、辅助文字 #70636a、分隔线 #eee0e2 与白色表面 #ffffff。字体沿用 Inter、苹方及微软雅黑，标题 27px、统计值 24px、表格正文 13px。页面按“标题及新增／导入 → 筛选 → 当前筛选汇总 → 计收明细及分页”排列，以月度经营明细的核对任务为中心，不增加装饰图表。

筛选区为账期、归属、状态、关键词及查询／重置分配不同宽度；窄屏改为分行布局。五项统计合并到同一汇总栏，生效认定金额使用深红强调，并保留待审与已认定的原有统计关系说明。权限说明移至表格底部，减少标题区文字密度。

表头、列宽和金额对齐规则集中定义。月账期与省份各 90px，地市／组织 150px，来源项目 240px，客户 160px，合同编号 150px，条款编号 90px，三项金额各 200px，办理状态 120px，详情 70px，总宽 1760px。长名称及编号完整换行；金额采用等宽数字、右对齐和单行展示，预留数据库允许的最大精度及负值空间。表格内部横向滚动，右侧详情入口固定，分页放在表格容器内靠右排列。

状态同时使用文字与浅色标签，区分未认定、待审核和已认定。未填写金额继续显示 --，显式零金额显示 0.00。查询过程中显示更新状态并禁用查询及翻页；详情返回和浏览器前后退时从 URL 恢复筛选值。空结果给出调整筛选的提示。

## 验证与范围

TypeScript／Vite 构建、全前端 Prettier 检查和 Git 空白检查通过。首轮隔离浏览器回归 20 项通过，覆盖创建、导入、认定审核、权限及分页；最终布局专项在 1440×1000 与 375×812 两种视口复验，2 项全部通过并人工检查截图。专项检查长文本、最大精度正负金额、表头与金额同轴、固定详情入口、筛选控件不重叠、详情返回、后退恢复、空状态和页面无整体横向溢出。

实现依据为 RevenuePages.tsx、revenue.css、计收接口类型与金额校验，以及新增的 revenue-list-design.spec.ts。功能权限、认定流程、导入规则及金额统计均沿用既有实现。验收使用一次性隔离数据库，不修改本地应用库。最终结果及截图见 revenue-list-design-acceptance-20261104 目录。
