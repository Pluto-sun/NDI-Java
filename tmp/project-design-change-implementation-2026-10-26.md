# 项目管理需求变更实施记录

日期：2026-10-26。本文供项目维护人员接续开发、联调及发布时使用，记录本轮代码改动、数据兼容方式和验收结果。需求依据为同目录 `project-design-change-analysis-2026-10-26.md` 及本次对话中已确认的人员绑定、督办兜底规则。

## 一、驾驶舱与列表

驾驶舱分为四个独立时间筛选区域。经营总览的月份范围控制首排指标、项目金额或分类分布，以及阶段或产品分布；区域经营分布的月份范围控制地图和省分排名；趋势分析与近期变动各使用自己的月份范围。切换全部、方案交流、招投标、签约、计收时，各区域保留已选月份。

指标卡已移除上期数值、较上期变化和迷你趋势图，后端也不再计算上期汇总。总览、区域、趋势使用明确的 `part` 参数分别查询，某一区域请求失败时保留该区域的错误反馈，不借用其他区域的数据。经营统计继续采用项目所属月份区间口径；近期变动按事件发生月份筛选，月末快照功能保持原有独立入口。

区域分布扩大了地图栏宽度和图形高度，增加放大、缩小、重置，以及拖拽和方向键平移。省分排名仍提供表格数据，地图颜色不是唯一的数据读取方式。

项目列表将已应用的筛选条件和页码写入地址参数。进入详情时，另外按当前账号和列表地址保存尚未执行查询的输入、更多筛选的展开状态及滚动位置。通过浏览器返回或详情页的“返回项目列表”链接返回时，恢复已应用查询和输入草稿，二者不会相互覆盖。高级筛选统一提供“项目负责人”，列表与 CSV 导出使用同一查询条件。

## 二、项目负责人

新增 `project_responsible_person` 作为负责人主模型，记录姓名、项目内职责、可选账号关联及展示顺序。每项目至少一人、最多一百人；同名人员保留为独立记录，不依据姓名自动合并。姓名本身不要求存在系统账号。

每人可不分配职责，也可分配一种职责。省分负责人每项目至多一人；地市客户经理和产品单位支撑专家可以多人。省分负责人绑定账号时，后端校验账号启用状态、本省归属及省分角色，并排除管理员；其他人员可关联已启用的系统账号。同一账号不可在一个项目重复绑定。关联和职责均不授予查看、编辑或审批权限，原有角色与省市范围继续决定权限。

创建页面和新导入模板改用项目负责人名单，导入姓名通过中英文分号或换行分隔。详情页新增“配置人员”弹窗，允许增删姓名、分配职责及搜索关联账号。保存与普通项目资料共用项目行锁和版本校验，并记录变更前后人员信息；已终止项目只读。

V38 自动将存量省分负责人、客户经理、支撑专家迁入新表，不删除历史人员信息。原人员字段保留为兼容投影，负责人列表为后续开发的主入口。旧三列导入模板仍可识别；没有匹配账号的旧姓名可以保留。历史迁移演练脚本也补充新表写入，原旧库仍以只读方式访问。本次没有执行真实旧库迁移，也未修改原始 Excel。

## 三、督办接收人

省分督办优先发送给项目内已配置且有效绑定的省分负责人。绑定缺失、账号停用或资格不符时，查找本省已启用的省分角色账号，排除管理员，按登录名升序、账号 ID 升序选第一位，只发送一人。无人符合时，本次扫描立即转交负责该省的接口人，不等待原有第三十三天节点。

通知中记录实际接收账号，审计中记录直接转接口人的原因。相同督办周期已经直接转交接口人后，第三十三天扫描不重复发送。接口人及集团的后续升级链路继续沿用既有规则。若接口人也未配置，记录无人可接收的审计信息，留待账号范围配置修正后重试。

## 四、行政区划目录

V39 建立版本化行政区划主数据，并补齐组织选项。当前固定版本为 2025-12-31，提供三十四个省级选项、三百七十二个地市选择项。地市选择项包含实际地级单位、省直辖县级单位，以及直辖市、港澳台的省级同名选择项；该数字不等于全国地级市数量。项目仍只有一个主归属省市。

目录来源为 [yescallop/areacodes](https://github.com/yescallop/areacodes) 的 CC0 数据镜像，固定提交为 `e2c2b2e1fb4ce1fb76e879aa0b80e229adaf950c`，文件为 `data/2025.txt`。上游说明其来源为国家地名信息库。本次官方服务直接访问返回 403，未独立逐项核验官方当前目录，因此这里明确记录固定数据版本，不声称与实时行政区划自动同步。后续调整应核实变化后新增迁移，不修改已发布迁移文件。

迁移优先按代码和规范化名称识别存量省分，再按本省精确地市名称补齐标准代码，保留原组织 ID 及项目、账号引用。既有无法匹配的组织记录、演示组织不会被直接删除或重新归属；它们属于兼容保留数据。管理员页面取消自由新增省市入口，后端旧新增接口明确返回目录只读错误，避免仅隐藏按钮仍能绕过限制。

## 五、代码入口与扩展约束

负责人控制器位于 `projects/controller/ProjectPeopleController.java`，业务协调位于 `projects/service/ProjectPeopleService.java`，校验与兼容转换位于 `ProjectResponsiblePersonStore.java`，批量人员查询和写入位于 `projects/mapper/ProjectResponsiblePersonMapper.java`。列表采用人员存在性子查询筛选，再按项目批量加载人员，避免分页重复和逐项目查库；账号搜索由数据库筛选并限制一次一百条，后续若需分页可扩展该独立目录接口。

前端人员弹窗独立为 `ProjectPeoplePanel.tsx`，月份控件独立为 `DashboardMonthRange.tsx`。新增代码注释使用中文，固定职责代码和 API 字段保持稳定。后续排产、计收、能力指标模块不应根据项目内人员职责直接授予权限，也不应继续增加平行的项目人员字段。

## 六、验收与本地启用

后端完整 `./mvnw -q verify` 通过：七十六项单元及架构测试、一百二十六项集成测试，无失败。随后针对导入同名人员保留规则再执行负责人及导入专项，共九项通过。迁移测试覆盖旧人员回填、标准目录数量、存量组织 ID 保留、金额保留和重复执行不重复增量。

迁移脚本的八项 Python 单元测试通过，覆盖历史日期、同名人员的独立职责及缺失姓名时使用原绑定账号姓名的兜底；仅使用模拟连接，没有访问旧库。测试命令使用已有 Python 环境运行：`backend/.venv/bin/python -m unittest discover -s scripts -p test_legacy_opportunity_date.py`，其中解释器位于旧项目，测试工作目录为 NDI-Java。

前端 TypeScript 检查、正式构建及 Prettier 检查通过。真实地图边界下的八项专项浏览器测试通过，覆盖桌面和 375px 窄屏的独立时间筛选、地图按钮和键盘操作、人员弹窗、绑定账号、唯一省分职责、多位客户经理、取消不落库，以及第二页往返与未查询输入保留。登录态的十二项浏览器测试通过，覆盖账号、密码、权限范围、备份、督办及目录只读。最终整套开发态浏览器回归七十项全部通过，包含桌面与窄屏两个视口；合计两种身份模式八十二项通过。

本次验收使用一次性 MySQL、MinIO 和独立端口，未操作运行中的 3307 应用数据，也未停止用户在 IDEA 中运行的服务。验收截图保留在 `tmp/design-change-acceptance-20261026/`。本地启用时先备份当前库，再重启 IDEA 中的后端，由 Flyway 顺序执行 V38、V39，随后刷新前端。前后端应一起更新，否则新版页面访问人员接口时，旧后端仍可能返回未找到。

V38 放宽旧省分负责人账号必填约束，新项目可能只有未绑定的姓名；回退版本时应同时评估数据库兼容性。行政目录后续通过新增迁移维护，保持已有项目的组织标识可追溯。用户原有部署说明、原始 Excel 和其他未关联文件未纳入本轮修改。

验收日志分别为 `tmp/design-change-backend-final.log`、`tmp/design-change-targeted-final.log`、`tmp/design-change-e2e-final.log`、`tmp/design-change-e2e-session.log`、`tmp/design-change-e2e-targeted.log`。浏览器验收容器与临时备份目录已由脚本清理。
