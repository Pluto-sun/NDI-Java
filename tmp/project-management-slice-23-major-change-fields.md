# 切片 23：分类金额与组合重大变更

## 业务与数据

重大变更增加 `FIELD_CHANGES` 类型，一份申请支持修改项目名称、总金额、网络化／格物／大数据／万悟金额及阶段。选中字段必须填写，重复字段、无实际变化、负数、超出两位小数或数据库精度的金额均拒绝；未选字段保留当前值。新增分类金额会建立对应分类记录，零金额仍是已填写金额。阶段仅允许回退或终止，正向推进继续使用阶段推进申请。

服务端先计算完整目标金额，再检查分类合计不超过目标总金额，因此支持同单同时调低总额和分类额。`V25` 的字段明细表冻结原值、目标值及展示顺序。审批前不改正式数据，驳回、撤销或冲突均不写入目标字段；原有单项申请与历史记录继续读取。

审批通过后，在项目行锁及原事务内共同应用名称、金额和阶段，保留唯一待审申请、指定审批人、48 小时截止和管理员不参与业务审批的规则。组合改名在审批时再次查重，重名则整单冲突。回退沿用合同字段清理规则，终止保留合同信息。仅分类子表变化时仍推进主档聚合版本，避免变更审计复用旧版本号。

## 统计、审计与界面

正式变更事件增加分类金额前后值。分类变更按申请月份进入月末状态事件，跨月通过时只修订受影响项目。修订表记录四类金额的前后值；旧记录缺失这些历史值时保持空值，避免伪装为零。状态事件增加写入序号，相同时间戳的多次审批按实际写入顺序重放。

项目详情将重大变更表单拆为独立组件。用户勾选字段、填写新值和原因，再指定审批人；审批详情逐项展示提交时原值与目标值。月末修订区展示实际发生变化的分类金额。金额差异使用十进制字符串展示，避免展示审批金额时再次转换为浮点数。

## 验证

集成验证覆盖组合生效、完整目标金额校验、重复字段、正向阶段拒绝、驳回与撤销、重名整单冲突、分类原值冲突、回退清理与终止保留、同刻分类审批版本及事件顺序、跨月分类修订和其他项目不受影响。浏览器验收增加勾选四个字段、指定审批、逐项对照以及通过前后核对正式数据的流程。

本轮 Maven 全量验证通过；组合变更集成测试 7 项、既有审批 33 项、督办 9 项和月末快照测试均通过。Chromium 桌面与 375px 窄屏共 4 条浏览器验收通过，包含督办闭环与组合变更审批。

复跑命令沿用 `./mvnw -q verify`、`frontend` 下的 `npm run format:check && npm run build`，以及根目录的 `scripts/run-project-e2e.sh`。测试时自动任务由测试代码显式调用，避免缓存测试上下文在容器关闭后自动扫描旧连接。所有数据库与对象存储验证均使用隔离容器。

实现与验证来源：旧版 `ChangeRequestCreate` 和重大变更表单；新版 `ProjectMajorChangeFields`、`ProjectFieldChangesIT`、`frontend/e2e/major-change.spec.ts`。
