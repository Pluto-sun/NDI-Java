# P2：项目重大变更审批切片实施记录

## 实施范围

本切片为项目名称、项目总金额、阶段回退和项目终止建立单独的重大变更申请入口；每份申请只处理一种变更。地市职责人员在本市项目上发起申请时，必须指定同省的省分三化、数字化或智能化负责人；省分职责人员在本省项目上发起时，必须指定对应省份的接口人。申请人与审批人不得相同，管理员即使兼任业务角色也不具备业务审批资格。发起人选择 `CITY` 或 `PROVINCE` 职责，服务端再次核验其角色与项目属地，避免仅凭前端选择决定审批路径。

申请记录冻结项目版本、原阶段、目标字段、变更原因、唯一审批人及提交时间。截止时间为提交后 48 小时。申请待审期间不修改项目主档；同一项目仅允许一条待审申请，并由数据库生成列唯一索引兜底。发起人可撤回，指定审批人可通过或驳回；驳回意见必填。提交、处理、撤回及版本冲突均写入独立的审批动作记录。

审批通过时，服务端在项目行锁内校验申请的基础版本，再更新项目主档，并写入项目变更事件。阶段回退和终止同时追加阶段里程碑。回退到“方案交流”或“招投标”会清空当前合同编号、签约金额，变更事件保留清理前后的值；终止保留合同字段。项目一旦终止，不受理新的重大变更申请。版本不一致的申请标记为 `CONFLICT`，接口返回 HTTP 409，发起人需刷新并重新申请。

## 接口与数据迁移

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/projects/{projectId}/major-changes` | 发起重大变更，返回待审申请。 |
| `GET` | `/api/v1/projects/approvals/{requestId}` | 发起人或指定审批人查看申请。 |
| `POST` | `/api/v1/projects/approvals/{requestId}/withdraw` | 发起人撤回待审申请。 |
| `POST` | `/api/v1/projects/approvals/{requestId}/decision` | 指定审批人通过或驳回。 |

`V4__create_project_major_change_approval.sql` 新增合同编号与签约金额、审批申请和不可变审批动作表。合同编号设置全局唯一约束，为后续“签约→计收”审批保留正式字段。审批申请表以 `request_type` 区分业务类型；后续阶段推进仍须在资料上传校验建立后接入，不允许用未经验证的附件标识替代“已上传”条件。

## 验证与后续边界

MySQL 集成测试覆盖审批前主档不变、48 小时截止、唯一待审申请、审批人越权、发起人撤回、驳回意见、分类金额上限、回退清理、终止保留和版本冲突。执行 `./mvnw clean verify` 作为完整验证。

本切片尚未实现正向阶段推进、MinIO 资料上传和关联、逾期提醒与通知投递，也未提供审批待办列表。下一切片应先完成资料上传闭环及文档可用性校验，再接入三次正向阶段推进；其后补审批待办、逾期扫描与通知。月末快照、Excel 导入和历史数据迁移仍按 P0 既定范围后续实施。
