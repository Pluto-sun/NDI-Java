# 导入、品牌、账号管理与排产计划需求分析

日期：2026-10-26。本文记录本轮需求及五项补充答复，供后续开发与验收使用。本轮仅进行分析和留档，尚未修改业务代码或数据库。

## 一、现有实现与调整范围

项目导入已经具备三步向导、未完成任务恢复、行修正和名称分档查重，但当前允许必填字段不映射后进入第三步补值。本轮需要将映射完整性提前校验，前后端同时阻止必填字段缺少映射时进入预检。

接口人范围目前允许一个省份对应多个接口人，数据库只有“接口人＋省份”联合主键，没有省份唯一约束；页面也直接展开每位接口人的省份选项。账号列表的服务端已有角色筛选能力，页面尚未使用，创建账号默认角色也未随列表视角变化。公共 Feedback 组件当前没有倒计时，不能直接给所有 Feedback 加五秒定时，因为其中还承载加载过程、校验错误和持续说明。

排产后端目前只有 production 模块标记，前端排产计划仍是占位页。本轮排产属于独立新业务，不是恢复旧系统的排产实现，也不要求先创建项目管理中的项目。计收、能力指标以及排产驾驶舱不纳入本次列表切片。

已检查项目根目录 logo.png，图片为 848×556，具有透明通道，内容为红色图形和深色“联通格物”文字。适合现有红白页面，保留原图颜色和透明背景；通过展示尺寸、留白及背景协调，避免将包含文字的完整 Logo 缩到难以辨认。

## 二、项目导入映射门槛

第二步先检查每个固定必填字段是否存在有效来源映射，包括源表头存在、映射不为空、同一源列不重复使用。缺少映射时标出缺失字段，禁用下一步；服务端也拒绝直接调用接口绕过。不能仅依靠前端禁用按钮。

“字段已映射但单元格为空”和“字段未映射”分开处理。前者进入第三步后按行报错，用户仍可在修正弹窗补值；后者不能进入第三步。源文件本身没有必填来源列时，需要补充源文件或选择合适的已有来源列，不再沿用当前“未映射后到第三步补齐”的说明。

建议保留旧人员模板兼容规则：统一“项目负责人”已映射，或旧省分负责人、地市客户经理、产品单位支撑专家字段组存在可用映射，视为满足人员来源门槛；每行仍必须解析出至少一位负责人。条件必填字段根据所选工作表、已映射的类别和阶段判断，不能把所有未使用类别的金额列都变成固定必填。字段内容本身无效时，仍由第三步逐行校验。

排产复用相同三步交互，但使用排产自己的必填字段和业务校验。每账号、每业务模块分别保留未完成任务，项目导入和排产导入不互相覆盖。

## 三、品牌与操作反馈

登录区和侧栏品牌区接入 logo.png，保留透明背景、比例和原始品牌色。页面主体继续采用白底、浅红层次与深红按钮，正文保持深色；不直接将图片拉伸为细长横条，也不对原图强制染色。浏览器小图标若后续替换，需要单独适配图形识别度，不把整幅含字图片直接缩到十几像素。

操作成功、上传成功、保存完成等轻量结果提示改为统一通知，默认显示五秒倒计时，结束后关闭，也允许手动关闭。新提示拥有独立计时标识，旧定时器不能关闭刚出现的新提示；悬停或键盘聚焦时可暂停计时，倒计时不逐秒打断读屏。

字段错误、失败重试入口、加载进度和持续性说明留在相应表单或区域中，不作为五秒后清空的结果提示。例如上传仍在进行时，进度不能因通知计时结束而消失。

## 四、接口人省份唯一与交接

目标约束为一个接口人可以负责多个省份，每个省份最多一个接口人，允许尚未分配。列表显示接口人已有账号、姓名、登录名、启停状态和负责省份摘要，点击对应账号的“配置”按钮后，在页内弹窗中多选省份。

未分配省份可勾选；当前账号已拥有的省份默认勾选且可取消；其他账号拥有的省份禁选，并在省份名称下面显示绑定账号姓名，必要时补充登录名以区分同名账号。占用信息必须来自完整省份分配关系，不能只从当前接口人列表页推断。保存时重新校验占用和版本，数据库增加省份唯一约束，防止两个管理员并发占用同省。

用户已确认增加交接：省份从 A 转给 B 时，将该省相关待审申请一并交给 B，并保留审计。迁移对象限于需要接口人处理的待审节点，不能将本来由省分负责人审批的地市重大变更转给接口人。已通过、驳回或撤销记录保留原审批人；原申请时间、审批截止时间和材料不重置，已逾期仍为逾期。交接调整审批责任，不赋予管理员代审批权限。

当前停用账号和移除接口人角色都会清除负责省份。实施时须将这些入口与交接规则统一：常规调整优先完成交接；紧急停用仍应立即生效，相应待审事项需明确列为待交接，在配置新接口人时完成移交，不能静默遗留。范围修改继续撤销相关旧会话、更新待办与通知。若存量数据存在同省多人，先生成冲突清单并确定保留与交接对象，不按排序擅自删除分配。

## 五、按角色管理账号

在“账号与组织”标题旁放置与现有页面风格一致的角色单选控件。列表只查询选中角色，可继续组合姓名或账号搜索、启停状态与分页；切换角色时回到第一页，记住最近选择或保留在地址参数中，不默认混列全部角色。

新建账号时预选当前角色。单选的是管理视角，不把整个账号模型改为只能拥有一个角色；保留已有合法兼任规则。一个合法多角色账号可在其各角色列表中出现，编辑时不能因当前筛选角色而丢弃其他既有角色。首访默认可使用现有的地市负责人角色，后续恢复管理员最近的选择。

## 六、排产计划字段及已确认规则

排产列表展示全部下列业务字段，使用紧凑表格和表内横向滚动，保留列标题和金额单位。页面提供新增入口；“新增排产”页面提供导入按钮，导入使用独立三步向导。建议列表提供月份、属地、接口人、项目、客户、类别和状态筛选，并在详情返回时保留查询条件及页码。

| 字段 | 填写要求 | 本轮口径 |
| --- | --- | --- |
| 接口人 | 必填 | 自由文本，不关联系统账号或接口人角色 |
| 排产月份 | 必填 | 年月，存为规范化月份，不等于创建月份 |
| 省份、地市 | 必填 | 使用已有行政区划目录，校验省市对应关系和账号数据范围 |
| 项目名称、客户名称 | 必填 | 独立文本，不强制选择项目管理已有项目 |
| 三化类别 | 必填 | 建议沿用当前稳定类别编码和多选方式 |
| 工业专网排产 | 选填 | 万元，非负，最多两位小数 |
| 格物平台排产 | 选填 | 万元，非负，最多两位小数 |
| 工业大数据排产 | 选填 | 万元，非负，最多两位小数 |
| 万悟平台排产 | 选填 | 万元，非负，最多两位小数 |
| 项目状态 | 选填 | 可空文本，不套用项目管理生命周期 |

用户已确认四个排产字段为金额，统一万元、最多两位小数，允许零、不允许负数。四项至少一项非空；只填零也属于有值，不能误判为空。其余未填项保留空值，列表显示“—”，不在存储或编辑时擅自改为零。本次不增加必填的“项目总金额”，也不强制校验排产合计与项目管理金额的关系。

类别与产品建议按现有编码对应：NETWORK 对应网络化和工业专网，GEWU 对应数字化中的格物平台，BIG_DATA 对应数字化中的工业大数据，WANGWU 对应智能化和万悟平台。按用户原文，所选类别不要求每项都填写排产金额，只要求四项合计至少一项有值；建议已填的排产产品须属于所选类别，防止类别与金额相互矛盾。

用户已确认唯一口径为“排产月份＋省份＋地市＋项目名称＋客户名称”。接口人不同也不能在同月、同属地、同项目及客户下新增第二条；不同月份允许分别记录。导入重复应报错或保留文件内首条，不静默覆盖或自动合并已有金额。修改既有记录须走明确编辑入口并校验版本。项目管理的全库同名或相似名称拦截不能直接套到排产，否则会误阻止同项目跨月记录。

用户已确认首版新增、导入、修改和删除无需审批，权限如下：

| 账号角色 | 可查看范围 | 可维护范围 |
| --- | --- | --- |
| 系统管理员 | 全国 | 全国 |
| 接口人角色 | 已配置负责省份 | 已配置负责省份 |
| 省分三化、数字化、智能化角色 | 本省 | 本省 |
| 地市角色 | 本地市 | 本地市 |
| 集团、数科、数智、广东 DPASS 等全国只读角色 | 全国 | 无 |

权限按实际登录账号及数据归属校验，不根据“接口人”文本判断。排产操作策略独立：项目管理中管理员不能手动创建项目，不能因此错误地禁止管理员新增排产。建议删除采用逻辑删除和审计，默认列表、查询及业务键校验只针对未删除记录；月份修改仍需重验唯一性。首版不引入月份封账、业务审批、项目状态机或历史快照。

## 七、模块边界与实施顺序建议

排产在现有 production 模块内组织 config、controller、domain、mapper、service、util 等职责，前端使用独立业务目录。复用账号、省市、对象存储和导入交互等基础能力，排产自己的字段、校验、重复键和写权限独立实现，不直接调用 ProjectImportService 承担排产业务。金额明细可按产品代码组织，列表投影为四个金额列，为后续增加产品留出空间。

接口人交接需要协调账号范围和项目审批，应由上层应用编排或公开模块接口协调，避免 identity 直接反向依赖 projects 形成循环。范围移交与仍待审申请的审批人切换需要保持一致；并发已经处理的申请不得被重新改为待审。交接审计必须区分管理员执行交接与接口人实际审批。

建议先完成项目映射门槛、Logo、通知及账号按角色管理，再处理接口人唯一分配和待审交接，随后开发排产列表与新增，最后接通排产导入及编辑、删除审计。接口人唯一约束实施前先做存量冲突预检，不直接让唯一索引迁移因重复数据而失败。排产导入复用已验证的上传、映射、预检、暂存、恢复和一次确认机制，仍只保留本模块未完成任务。

验收重点包括：前后端同时拦截缺少必填映射；已映射但空值仍按行报错；通知关闭不会丢失表单错误；省份全局占用、并发唯一和交接回滚；角色单选不丢既有合法兼任角色；排产金额零值与空值区分；同月重复阻断、跨月允许；各角色省市范围；导入恢复和完成后禁止续导。

## 八、结论与确认状态

五项补充问题均已答复：排产金额单位及精度、项目状态文本、排产维护权限及无审批、同月业务唯一键、接口人交接待审申请，现阶段没有阻止进入开发的业务问题。

本文其余标注“建议”的内容属于实施口径建议，包括兼容旧人员映射组、类别与金额对应、角色管理视角保留兼任、通知与持续错误区分、逻辑删除及模块化实现。尚未查询真实应用库的省份重复分配情况；若实施前预检发现冲突，需要根据具体清单确定保留和交接对象，不能凭分析擅自选择账号。
