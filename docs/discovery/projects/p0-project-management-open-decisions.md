# P0：项目管理定版决策清单

**状态：** P2 前置业务决策已关闭

**使用方式：** 本清单保留 P0 决策证据。P2 以[项目管理规则澄清](p0-project-management-rules.md)和[项目参考数据字典](p0-project-reference-data.md)作为可实现基线。

## 一、已定版结论

2026-10-15 已确认项目生命周期固定为“方案交流 → 招投标 → 签约 → 计收”，并保留“已终止”状态；所有正向阶段推进均提交审批，审批通过后才更新项目当前阶段和阶段里程碑。`collection` 负责计收明细，不替代项目生命周期阶段。

2026-10-19 已确认：已终止项目暂不允许恢复，`TERMINATED` 为首发终态；长期采用月末快照统计，但 P2 不建设历史月末快照读模型，也不采用会改写旧月份数据的唯一归属月事实表。

2026-10-19 已确认：项目合并不纳入当前系统范围；审批自提交时刻起 48 小时到期；终止与回退不要求材料，重大变更由用户经指定入口主动发起，管理员不参与业务审批；接口人可追加进展、上传资料和在授权范围内进行 Excel 项目导入。

## 二、已关闭的 P2 前置决策

| 编号 | 定版结论 | P2 验收重点 |
| --- | --- | --- |
| PRJ-03 | 已终止项目不可恢复。回退经重大变更审批生效；目标阶段低于签约时清空当前合同编号和签约金额，原值保留于变更历史。终止不清空既有字段。项目合并不在 P2 范围。 | 回退字段清理、终止字段保留、终态拦截和无合并接口。 |
| PRJ-04 | 审批申请指定唯一审批人，截止时间为提交后 48 小时；终止、回退和名称、金额等重大变更不要求材料，变更原因必填；管理员无业务审批权限。 | 唯一处理人、`submitted_at + 48h`、资料校验、逾期提醒和管理员越权拦截。 |
| PRJ-05 | 三化类别和客户行业采用稳定代码。项目总金额、每个已选类别金额均必填且非负，类别金额合计不得超过总金额。省分负责人关联本省已启用省分负责人账号，地市客户经理为必填自由文本。 | 参考数据、金额校验、人员范围校验和导入预检。 |
| PRJ-07 | 接口人无项目创建、普通字段编辑和责任信息修改权限；其具备追加进展、上传资料、授权范围内 Excel 项目导入和指定审批任务处理权限。 | 权限正反向测试和数据范围过滤。 |
| PRJ-09 | 首轮迁移包含所有记录状态为有效的项目，包括已终止项目；迁移主档、进展、阶段里程碑、责任信息和导入来源；不迁移审批、审批审计和附件。 | 源记录基线、映射覆盖率、时间线顺序和迁移验收对账。 |

## 三、已定版但暂不实施的统计能力

| 编号 | 定版结论 | P2 约束 | 后续实施条件 |
| --- | --- | --- | --- |
| PRJ-10 | 项目经营趋势长期采用月末快照。已终止项目默认排除；项目总金额不得为空。 | P2 不建设历史月末快照读模型，不建立会删除或改写旧月份记录的 `project_monthly_fact`。项目阶段与受控变更必须保留不可变里程碑和版本化变更记录，以支持后续回算。 | 统计分析迭代时确定快照生成时点、重算范围、维度、金额取值与“含已终止项目”筛选规则。 |

## 四、首个 P2 纵向切片范围

项目管理已具备创建首份业务 Flyway 迁移和进入 P2 的条件。首个纵向切片包含身份与组织最小引用、项目创建和查询、金额与责任校验、进展追加、阶段推进和重大变更审批、项目资料上传入口、Excel 导入以及审计与版本化变更记录。设计必须满足 PRJ-10 的约束：以追加式里程碑和版本化变更记录作为未来月末快照的可回算来源，不提前建设统计读模型。

项目名称查重策略、项目合并、历史审批与审计迁移、历史附件迁移和历史月末快照查询均明确排除在首个纵向切片外。P2 不为这些能力创建预占业务字段或接口；后续另行形成范围、规则和迁移方案后再实施。
