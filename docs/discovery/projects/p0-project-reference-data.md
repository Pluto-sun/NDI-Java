# P0：项目管理参考数据字典

**状态：** P2 设计基线

**范围：** 项目三化类别、客户所属工业行业、省分负责人和地市客户经理的存储与校验规则。

## 1. 三化类别与金额

项目类别金额采用一行一个类别的关系模型，不使用网络化、格物、大数据、万悟四个固定金额列。关系记录的业务键为“项目标识 + 类别代码”，字段至少包括 `category_code`、`expected_amount`、创建时间和更新时间。该设计支持类别稳定、金额校验一致，也为未来增加类别保留扩展空间。

| 类别代码 | 展示名称 | 归属 |
| --- | --- | --- |
| `NETWORK` | 网络化 | 网络化 |
| `GEWU` | 数字化（格物） | 数字化 |
| `BIG_DATA` | 数字化（大数据） | 数字化 |
| `WANGWU` | 智能化（万悟） | 智能化 |

项目至少选择一个类别。每个被选择类别必须存在一条金额记录，`expected_amount` 为非空、非负、两位小数的万元数值；未选择类别不得创建金额记录。项目总金额同为非空、非负、两位小数的万元数值，所有已选类别金额之和不得超过项目总金额。数值 `0.00` 表示已明确填写的零金额，与空值不同；本基线不将零金额自动视为缺失。

## 3. 责任字段

省分负责人保存 `province_leader_user_id` 及姓名快照。提交在线表单或导入预检时，系统校验该账号已启用、所属省分与项目省分一致，且具备省分三化负责人、数字化负责人或智能化负责人中的至少一个角色。账号后续停用不改变项目历史快照，但阻止其作为新建或变更后的省分负责人。

地市客户经理为必填自由文本，字段名为 `city_account_manager_name`；它不关联账号或人员目录，也不产生读取、编辑或审批授权。产品单位支撑专家沿用独立的多人责任关系，其责任信息同样不授予项目权限。

## 4. 取证与适用版本

三化类别沿用旧系统稳定代码 `NETWORK`、`GEWU`、`BIG_DATA`、`WANGWU`。工业行业的名称范围来自旧系统的 41 项受控选项，代码按国家统计局现行《国民经济行业分类（GB/T 4754—2017）》的门类和大类编码规则设计。本字典自 P2 首份项目业务迁移起生效。
