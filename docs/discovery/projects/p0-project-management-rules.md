# P0：项目管理规则澄清

**状态：** P0 工作稿，未授权创建项目业务表

**范围：** `projects` 模块的项目主身份、项目生命周期、过程记录、权限、导入和模块内统计分析

**不在范围内：** 排产、计收、能力指标的领域规则；对象存储实现；通用流程引擎；业务 Flyway 迁移

## 1. 结论与使用边界

`projects` 持有项目主身份和项目生命周期，其他业务模块只保存项目标识及必要业务快照。项目工作台／统计分析属于 `projects`，其查询模型只读取本模块公开数据；`reporting` 只处理跨模块专题分析，不承接项目工作台。

本文件将旧系统中的已验证事实、当前实现行为和新系统建议边界分开描述。出现冲突的规则不转写为新系统结论，而是进入 [定版决策清单](p0-project-management-open-decisions.md)。在清单中的阻断项关闭前，不创建 `projects` 的项目、进展、阶段、变更、导入等业务表，也不编写相应 Flyway 迁移。

## 2. 领域术语

| 术语 | 定义 | 边界与约束 |
| --- | --- | --- |
| 项目 | 以稳定项目标识管理的一项工业三化业务机会或已签约事项。 | 项目名称是展示和查重依据，不是跨模块关联键。 |
| 项目编号 | 项目生效后生成的业务可读编号。 | 草稿不占用编号；编号生成规则须可审计。 |
| 项目主身份 | 用于跨模块引用的不可复用项目标识。 | 项目更名、属地调整或历史迁移不得改变该标识。 |
| 项目生命周期阶段 | 项目在项目管理范围内的当前业务位置。 | 当前阶段由已生效里程碑推导并冗余保存；不得以直接覆盖方式改写历史。 |
| 阶段里程碑 | 项目进入某个阶段的一次事实记录。 | 包含阶段、生效日期、来源、操作人和说明；同一阶段再次进入时新增记录。 |
| 项目进展 | 对项目当前进展、下一步动作、责任和支撑诉求的追加式记录。 | 已保存记录不物理删除；纠错通过新增更正记录关联原记录。 |
| 重大变更 | 对已生效项目产生治理影响的受控修改。 | 审批前保留生效值；申请保存版本、前后值、原因和附件引用快照。 |
| 项目合并 | 确认多个项目主档实为同一项目的治理动作。 | 保留主项目与被合并项目均不物理删除；被合并项目保留跳转、来源与审计链。 |
| 项目属地 | 项目归属的省分和地市。 | 地市必须隶属所选省分；数据范围基于授权组织树计算。 |
| 项目责任 | 对项目承担省分统筹、地市客户、产品支撑等职责的人员关系。 | 人员目录与登录账号分离，关系中保留人员名称快照。 |
| 历史导入 | 将旧系统或 Excel 中的项目记录纳入新系统的受控过程。 | 保留源系统、批次、工作表、行号、原始值、转换结果和处置结果。 |

## 3. 模块职责与聚合边界

项目主身份、项目基础资料、阶段里程碑、进展、责任关系、名称别名、变更申请和项目专属导入属于 `projects`。附件内容与对象元数据属于 `documents`，项目只保存文档关联；身份、组织和数据范围权威来源属于 `identity` 与 `organization`；审批任务的通用执行能力属于 `workflow`，项目模块只定义何种项目变更需要审批以及审批通过后的业务生效动作。

项目金额在项目管理中仅表达商机或项目预期金额及其确认状态，不承担合同、应收、实收、冲销和对账职责。此边界避免将计收领域状态回填为项目阶段或项目金额。项目阶段中是否保留“签约”以及项目与计收模块的交接事件，均须经业务评审定版。

## 4. 候选字段清单

字段按业务含义分组，而非照搬旧库表。字段代码在定版后再确定；本节用于确认首发数据最小集、字段归属和导入要求。

| 字段组 | 候选字段 | 规则与来源 | 首发口径 |
| --- | --- | --- | --- |
| 主身份 | 内部项目标识、项目编号、记录状态、版本号 | 旧系统以 UUID 和 `Project_ID` 区分内部关联与业务展示。 | 生效项目必须具有内部标识、编号和乐观锁版本；草稿独立保存。 |
| 组织属地 | 省分、地市、组织名称快照 | 旧系统以省市字典校验归属和查询范围。 | 省市关联由 `organization` 校验；项目保存引用及名称快照策略由迁移方案定版。 |
| 名称与客户 | 项目名称、名称标准值、名称核心值、历史别名、客户名称、客户行业 | 旧系统按同地市名称查重，名称变更保留别名。 | 项目名称为必填；客户名称的在线新建与历史导入规则分开处理。 |
| 建设内容 | 原始建设内容、客户需求、产品推进内容、应用场景、备注 | 旧台账中的建设内容存在半结构化标签文本。 | 原始值保留，结构化字段仅在有明确来源或人工录入时写入。 |
| 项目分类 | 三化类别、重要度、签约主体 | V1.2 增加签约主体，废弃三化标杆和总投总签标签。 | 类别采用稳定代码的多值关系；废弃字段不进入新业务接口。 |
| 生命周期 | 当前阶段、阶段日期、最近活动时间、统计归属月份 | V1.2 将统计月份与最近更新时间分开；阶段变化产生里程碑。 | 两类时间的更新条件须以定版状态机为准。 |
| 预期金额 | 项目总金额、分类预计金额、各金额确认状态、拟招标日期及精度 | 旧系统金额单位为万元，未知金额与零值含义不同。 | 金额使用定点小数；空值表示未知，零表示已知为零；分类金额合计不得超过项目总额。 |
| 项目责任 | 省分负责人、地市客户经理、产品单位支撑专家及其他协作职责 | V1.2 用组织与责任信息组替代旧“项目负责人”单字段。 | 单人责任与多人支撑关系分别建模；人员快照保留于关系记录。 |
| 过程记录 | 进展日期、进展内容、下一步动作、下一步责任、到期日、支撑诉求、更正关联 | 旧系统采用追加式进展和更正说明。 | 进展正文与下一步动作不得为空；重点项目到期日规则需定版。 |
| 治理与来源 | 建立来源、导入批次、来源行号、创建人与时间、更新人与时间、规则版本 | 旧系统留存在线／导入来源、批次和行号。 | 迁移、审批和规则调整均须保留来源与版本证据。 |

下列字段不纳入 `projects` 的首发业务模型：附件对象键、附件本地路径和文件哈希属于 `documents`；合同编号、签约金额、应收、实收和冲销属于 `collection`；排产结果属于 `production`；能力计算结果属于 `capabilities`。旧系统中已存在的 `contract_no`、`signed_amount` 或本地附件路径，只能作为历史源字段参与迁移评估，不得据此确定新模块归属。

## 5. 状态与变更规则

项目管理至少存在三个彼此独立的状态轴。将草稿、项目是否有效、项目阶段和审批进度混在单一状态字段中，会造成列表、权限和统计口径相互污染。

| 状态轴 | 候选状态 | 约束 |
| --- | --- | --- |
| 草稿 | 编辑中、已提交、已放弃 | 草稿不是生效项目，不参与项目编号、查重结果和工作台统计。 |
| 项目记录 | 生效、已合并 | 已终止属于生命周期阶段而非记录删除；已合并项目只读并跳转保留主项目。 |
| 项目生命周期 | 方案交流、招投标、签约、已终止，以及经评审确认的其他阶段 | 当前阶段来自最新生效里程碑；阶段词表、正向路径及“计收”归属尚未定版。 |
| 变更申请 | 待初审、待终审、已通过、已驳回、已撤回、冲突 | 待审批申请不覆盖项目生效值；终审时校验申请基础版本。 |

项目生效的创建动作应在同一事务内完成项目主身份、首条里程碑、首条进展、责任关系和审计记录。阶段变化应新增里程碑，不得覆盖既有阶段记录；非阶段更新只更新最近活动时间，是否更新统计归属月份遵循定版口径。名称、重大金额、阶段回退、终止、恢复和合并属于候选受控变更类型。重大金额阈值、正向阶段是否需审批、阶段推进时的资料要求及审批路由均见定版决策清单。

## 6. 权限矩阵

新系统不将旧系统角色代码直接固化到 `projects`。`identity` 与 `organization` 提供用户、角色、组织范围和授权关系；项目模块仅校验权限点、项目状态和数据范围。下表以旧系统已验证职责为基础，表示首发所需的能力集合，不表示最终角色命名。

| 权限点 | 属地填报职责 | 省级统筹职责 | 审核职责 | 平台管理职责 | 关键约束 |
| --- | --- | --- | --- | --- | --- |
| `project:read` | 查看授权属地项目 | 查看授权省级范围项目 | 查看获授权审核范围项目 | 仅为配置、导入诊断取得最小定位信息 | 服务端按组织范围过滤，前端隐藏不构成授权。 |
| `project:create` | 在授权属地创建项目和草稿 | 在授权省级范围创建项目和草稿 | 无 | 无 | 省市由当前授权范围校验，不采信客户端传值。 |
| `project:update_normal` | 维护被授予维护权的项目 | 维护被授予维护权的项目 | 无 | 无 | 已合并项目禁止写入；进展保持追加式。 |
| `project:advance_stage` | 对授权项目发起定版后的正向阶段动作 | 对授权项目发起定版后的正向阶段动作 | 按流程处理或无权 | 无 | 是否直接生效由状态机决策确定。 |
| `project:request_change` | 对授权项目发起受控变更 | 对授权项目发起受控变更 | 无 | 无 | 申请冻结项目版本、规则版本和前后值。 |
| `project:review_change` | 无 | 无 | 仅处理分配给本人的审批节点 | 无 | 申请人与处理人职责分离，审批范围由任务快照约束。 |
| `project:merge` | 发起合并申请 | 发起合并申请 | 依定版流程审查 | 无 | 合并生效后保留被合并项目的可追溯关系。 |
| `project:import` | 仅导入授权属地的历史或新增项目 | 仅导入授权范围项目 | 无 | 全国历史迁移按独立授权执行 | 每行均执行省市、字段、金额和查重校验。 |
| `project:export` | 导出授权范围结果 | 导出授权范围结果 | 导出获授权审核范围结果 | 无 | 导出继承读取范围，排除附件内容和运行敏感信息。 |

项目维护资格不等同于项目读取资格。旧系统采用“创建人、项目责任人或显式协作授权”三个来源，且省级查看地市项目不自动获得编辑权。新系统保留这一职责分离原则；协作授权的授予人、范围、期限、原因和撤销记录须由权限设计说明定版。

## 7. 历史数据映射策略

历史迁移不采用旧库结构的逐表复制。每批迁移执行“抽取、标准化、预校验、人工处置、确认写入、核对与回退”闭环，迁移过程保留源记录而非覆盖源数据。项目主身份映射表、导入行结果、错误与预警代码、原始行内容和转换后字段均属于迁移审计证据。

| 旧来源 | 新项目管理归属 | 映射规则 | 处置要求 |
| --- | --- | --- | --- |
| 旧 `project` 主档 | 项目主身份与基础资料 | 旧项目 ID 仅作为源标识；新项目标识与业务编号按新规则生成。 | 保存源系统、源主键、导入批次和映射结果。 |
| 旧 `project_finance` | 预期金额与拟招标时间 | 金额按万元、定点两位小数导入；空值与零值保持语义差异。 | 分类金额超总额、负数或非法数值阻断该行。 |
| 旧 `project_category` | 项目分类关系 | 按定版分类字典映射稳定代码。 | 无法识别的类别进入处置清单，不以自由文本代替代码。 |
| 旧 `project_member` 与负责人文本 | 项目责任关系及原始责任文本 | 优先映射 V1.2 的省分负责人、地市客户经理和产品支撑专家；无法可靠拆分时保留原文。 | 缺失必填责任字段的历史项目进入质量清单，不阻断历史只读核对。 |
| 旧 `stage_milestone` 与当前阶段 | 生命周期阶段及里程碑 | 已中标的处理、计收阶段归属和缺失里程碑补录遵循定版决策。 | 系统迁移生成的记录必须标识迁移来源，不伪造人工操作人。 |
| 旧 `project_progress` | 追加式进展记录 | 保留进展日期、内容、下一步、责任、到期日和来源顺序。 | 无法解析的日期或空内容分别进入失败或质量处置清单。 |
| 旧 `change_request`、`approval_task`、`audit_log` | 历史审计与审批证据 | 首发不假定旧流程记录能继续流转。 | 迁入只读历史档案或保留源系统核对范围，由迁移方案决定。 |
| 旧 `project_attachment` 本地文件 | 文档关联 | 文件内容和元数据迁入 `documents`；项目只保存新的文档关联。 | 以对象哈希、文件数和关联数核对，不迁移本地绝对路径。 |
| Excel 样例与导入批次 | 受控导入批次 | 按工作表、表头、行号和人工映射进行标准化。 | 强重复、候选重复、失败和质量预警分别记录，禁止静默修正。 |

迁移验收至少核对项目数、稳定映射数、失败数、预警数、阶段分布、金额汇总、附件对象数和抽样项目的时间线完整性。新旧系统切换前，新系统先承担只读核对；开放写入后不得长期双写。

## 8. 项目工作台与统计分析

`projects` 工作台面向本模块的待办、风险和项目经营视图，按当前用户的数据范围执行。首发统计候选包括项目数量、预期项目总金额、分类预计金额、阶段分布、项目所属月份趋势、地域分布、超时项目和待完善项目。每一项指标须在定版时定义统计主体、时间口径、阶段筛选、组织范围、是否计入已终止或已合并项目、空金额处理方式和下钻清单。

统计读模型只能从 `projects` 的生效项目、里程碑、进展和经定版的项目金额快照构建。项目工作台不读取排产、计收或能力指标的私有表；需要呈现跨模块经营关系时，由 `reporting` 建立专题分析并使用各模块公开契约。
