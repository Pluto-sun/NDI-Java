# P2 项目管理 MVP 实施说明

## 1. 本次交付边界

本次交付项目管理的首个纵向切片：组织和账号最小引用、项目创建、按数据范围查询、三化金额校验、初始进展、首次阶段里程碑及创建事件留痕。它为后续阶段推进审批、重大变更、资料归档、Excel 导入和工作台统计提供稳定的项目主身份与事件来源。

本次不实现审批单、阶段推进、重大变更、附件、导入任务、历史数据迁移和月末快照。它们不会以预留空字段的方式写入项目主表，而会在各自规则明确后建立独立表和接口。

## 2. 模型与数据所有权

`organization` 管理省分和地市；`identity` 管理账号、角色及账号归属，并向项目模块提供“可创建”和“可读取范围”两个权限点；`projects` 管理项目主档、三化类别金额、阶段里程碑、项目进展和项目变更事件。项目模块不直接固化旧系统角色代码。项目内部主键为 UUID，项目编号为可读的业务编号，不能以项目名称作为关联键。

创建项目时，系统在同一事务内写入以下记录：

| 记录 | 作用 |
| --- | --- |
| `project_project` | 项目主档和当前正式阶段；初始阶段固定为“方案交流”。 |
| `project_category_amount` | 已选择的三化类别及对应预计金额。 |
| `project_stage_milestone` | “方案交流”首次进入的不可变更里程碑。 |
| `project_progress` | 首条项目进展和下一步动作。 |
| `project_change_event` | `PROJECT_CREATED` 创建事件，用于版本演进和审计追溯。 |

41 个工业行业门类以 `project_industry_reference` 管理，初始数据来自 P0 已确认的 GB/T 4754-2017 口径。三化类别固定为 `NETWORK`、`GEWU`、`BIG_DATA`、`WANGWU`。

## 3. 已实施业务校验

- 项目总金额必填且不得小于零；至少选择一个三化类别。
- 每个已选类别都必须给出金额，金额不得小于零，类别不得重复，类别金额合计不得超过项目总金额。
- 省分与地市必须存在、启用且属于同一组织层级。
- 行业代码必须是启用的参考数据。
- 省分负责人必须是项目所属省分内启用的省分三化、数字化或智能化负责人账号。
- 地市三化负责人只能在本人省市范围创建；省分三化、数字化或智能化负责人可在本人省内创建。
- 列表查询按身份模块计算出的省级或市级数据范围过滤；接口人可在其授权省份查询项目，但不会因本次实现获得项目创建或普通字段编辑权限；集团类账号和管理员没有兜底业务权限。

## 4. 接口与本地联调

已提供以下接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/v1/projects` | 创建项目。 |
| `GET` | `/api/v1/projects?page=0&size=20` | 查询当前账号数据范围内的项目。 |

`local` 环境使用请求头 `X-NDI-Actor-Id` 传入已存在账号的 UUID，供前后端联调使用。该适配器仅在 `local` Profile 生效；生产认证接入后必须由正式认证机制生成同一业务账号标识，不能沿用该请求头。

在调用接口前，应先由组织与账号管理能力准备省分、地市、账号、角色和行业参考数据。该切片不自动写入演示账号或组织数据，避免开发种子污染实际环境。

## 5. 后续切片约束

阶段推进和重大变更必须以审批通过作为更新项目主档的唯一入口；待审批申请不得提前修改正式阶段、金额或合同字段。阶段回退至“签约”之前时清空当前合同编号和签约金额，已终止项目不清空字段且暂不支持恢复。审批、资料和导入功能需要分别持有自己的申请、对象存储引用和任务记录，不能将大字段或附件路径塞入 `project_project`。

项目变更事件和阶段里程碑从本次开始追加保存。未来建立月度快照时，应由这些不可变更事实生成月末快照；不得通过覆盖同一项目的历史月份记录来改写既往统计。

## 6. 验证要求

本次代码以 Spring Modulith 架构测试约束跨模块访问，使用单元测试验证创建时的金额规则和初始记录写入。合并或部署前执行：

```bash
./mvnw clean verify
```

该命令同时执行 Flyway 迁移、模块边界、接口契约与 MySQL 集成验证。
